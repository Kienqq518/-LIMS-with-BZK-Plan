## 一、这份契约要解决什么

三段之间只靠一个东西传递信息：**这份 Excel**。它必须同时满足两个互相拉扯的要求——

- **人能读懂**：专家在 F2 要能扫一眼就找到该改的格子，不会因为在跟一个序列化格式搏斗而放弃复核。
- **机器能校验后入库不报错**：F3 要能在写入前把真实系统的全部强校验（试验编码大类内绝对唯一、参数名称单样品内唯一、符号不冲突、标称值被判定引用不可删、区分型号一旦挂型号不可关闭……）全部预演一遍，而不是写一半炸掉。

所以契约不是「把 Word 里的表格原样搬进 sheet」，而是**把抽屉的数据模型摊平成行列**。附件1-4 里 115 张表按语义归并到 22 张 sheet，一张 sheet 对应抽屉里的一个实体层级。

## 二、七条设计原则

1. **sheet-per-entity，不是 sheet-per-table。** 一行 = 一个实体实例（一个样品 / 一个试验项 / 一条标称值 / 一行映射数据）。
2. **稳定业务主键，绝不用行号当外键。** 专家在 F2 会排序、筛选、删行、线下改完传回来，行号一定会变。父子之间只靠 key 列关联。
3. **表头固定在第 1 行，禁止合并单元格。** Word 里的合并单元格在转换时展开成重复值 + 一个 `分组` 列，避免解析歧义。
4. **值与元数据分离。** 每个由 AI 产出的字段，其置信度记在 `C0_待定项`，不污染数据列本身；F2 的着色靠这张表驱动。
5. **导入顺序 = 拓扑顺序。** sheet 名前缀 `00/10/…/D0` 就是导入次序；前置实体缺失即整包拦截，不允许静默跳过留下半成品。
6. **一个 .xlsx 可含多个任务，一个任务只处理一份标准文件。** 客户能力范围常覆盖十几份标准，拆成十几个文件会把 F2 的复核切碎。所有顶层 sheet 带 `任务键`（= 标准文件编号）列，`10_分类路径` 起就按任务分组；定稿与入库仍以「任务 → 样品分块」为单位推进。
7. **契约必须能吃「不是 F1 生成的包」。** 附件1-4 那四份人工 Word 拆解稿转成的 Excel，要能直接进 F2/F3——这是契约通用性的验收用例。

## 三、包结构

```
<标准文件编号>.xlsx
├── 00_包信息        版本、来源、任务标识、置信度图例
├── 10_分类路径      大类 / 样品分类树 / 标准文件节点
├── 20_样品          样品基本信息（含电缆属性）
├── 30_规格参数      规格参数全局定义
├── 40_型号          型号
├── 41_型号规格赋值  型号 × 规格参数 → 赋值方式与可选项
├── 50_试验项        试验项（挂在型号或样品上）
├── 51_试验依据      试验项 → 标准文件 + 章节
├── 52_试验子项      试验子项
├── 60_控制参数      预设值
├── 61_映射明细      控制参数与标称值共用的「自变量-因变量」数据行
├── 62_条件规则      条件映射 / 条件修约的 If-Then 规则
├── 70_测量参数      实测值
├── 71_参数可选项    下拉选项类型的可选项与默认值
├── 80_计算参数      计算值（含公式与绑定层级）
├── 90_标称值        标称值（六种类型）
├── A0_判定配置      结果判定主配置（判定参数 / 层级 / 模式）
├── A1_判定条件      判定条件行
├── A2_结论映射      条件群 → 结论
├── B0_采集配置      计算顺序与是否覆盖
├── C0_待定项        置信度与待人工回答的问题
└── D0_校验规则      本包启用的校验规则清单（F3 报错时引用其编号）
```

**AI 分级**（贯穿所有 sheet 的一列语义）：

| 级 | 含义 | 典型字段 |
|---|---|---|
| **A 自动** | 有权威来源可直接核对 | 样品名称、标准号、试验名称、单位、测量次数 |
| **B 核对后** | 报告/记录单里有值，但必须回到检测依据标准文件验证才算数 | 标称值数值、技术要求文本、参数编码后缀 |
| **C 必须问人** | 输入文件里根本不存在，只能问 | 检测类别、映射类型、修约方式、判定模式、判断层级、是否覆盖 |

## 四、列定义

约定：`必填` 列的 `●` = 硬必填（缺了 F3 直接拒绝），`◐` = 条件必填，`○` = 选填。
`键` 列标注该列是否作为其他 sheet 的外键目标。

### 00_包信息

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 项 | 文本 | ● | 固定字段名：契约版本 / 任务列表 / 目标大类 / 稿件版本 / 生成时间 / 来源文件 |
| 值 | 文本 | ● | |
| 备注 | 文本 | ○ | |

`契约版本` 必须是 `v0.1`；F3 遇到不认识的版本直接拒绝，不做兼容猜测。
`任务列表` 一行列出本包内所有任务：`任务键 | 标准文件编号 | 标准文件名称 | 目标大类 | 状态`。

**任务键（`任务键` 列）**：一包多任务的分组维度，取值 = 标准文件编号。它出现在
`10_分类路径 / 20_样品 / 50_试验项 / 90_标称值 / A0_判定配置 / C0_待定项` 六张顶层 sheet 上；
其余 sheet 通过外键链回到 20 或 50，不再重复携带。F2 的任务切换、F3 的分块入库、
C0 的提问归属都按 `任务键` 分组。

`契约版本` 必须是 `v0.1`；F3 遇到不认识的版本直接拒绝，不做兼容猜测。

**试验编码生成规则**（对齐真实数采表名，已由数采表清单验证）：

```
wz_ + 一级样品分类缩写 [ + 更下层样品分类缩写 … [ + 样品名称缩写 ] ] + 型号缩写 + 试验项名称缩写
└ 物资大类固定前缀        └ 可续接多层，直到样品名称缩写为止
```

| 例 | 拆解 |
|---|---|
| `wz_dldl_lhjx_insul` | wz + dldl（电力电缆类）+ lhjx_insul（老化前绝缘的机械性能试验） |
| `wz_dldl_jgcc1_jgcc1_cond` | wz + dldl + jgcc1（结构尺寸检查1）+ jgcc1_cond（试验子项：导体） |
| `wz_bhg_dck_lccj` | wz + bhg（电缆保护管）+ dck（带承口样品）+ lccj（落锤冲击） |
| `wz_dldl_sssy` | wz + dldl + sssy（XLPE绝缘的收缩试验） |

冲突处理：**加 `_2`、`_3` 后缀，不用流水号**。理由：数采表名会被人直接读，`jgcc1_t_2` 一眼看出是 `jgcc1_t` 的重号变体；`sys0007` 混在名称缩写里反而更难查。

> 校验 **V05**：`试验编码` 必须在**大类范围内绝对唯一**，且匹配 `^[a-z][a-z0-9_]*$`（小写字母开头，只含小写字母、数字、下划线）。F3 按上述规则自行推导一遍，与 Excel 里的值不一致时进 C0 提问，不静默改写。
> 校验 **V06**：`检测类别` 的每个值要么命中字典，要么在 `C0_待定项` 里挂着一条「新增字典选项」的待确认问题；两者都不满足 ⇒ 阻断。
> 口径说明：**不要求必须命中字典**——标准文件里出现而字典没有的选项，系统要能新增。硬命中会整包卡死，而「型式检验 / 型式试验」这类同义不同名恰恰是能力文件与报告里最常见的。

| 未验证 | 值有来源但标准文件缺失或没找到条款 ⇒ 「缺哪个标准文件」本身是一条问题 |
| AI推断 | 输入里没有、由 AI 推导（检测类别、映射类型、判定模式等） |
| 无来源 | 空，排队待问 |

> 注：**报告模板里抄到的值不自动算已验证**——检测依据标准文件才是最终权威。

### D0_校验规则

把本文 V01–V22 平铺成机器可读的一行一条：规则ID / 目标sheet / 目标列 / 规则表达式 / 严重级（阻断/告警）/ 失败提示文案 / 触发时机（F2重算 / F3预检 / F3写入）。

F3 的报错信息一律带规则ID，专家在 F2 能直接按 ID 筛出问题。

## 五、F3 导入的事务边界

按之前定的：**任务边界 = 标准文件，定稿与入库挂在样品分块上**。

```
预检（整包，只读）
  ├─ 跑 D0 全部规则，产出「预检报告」，不写库
  └─ 有阻断项 ⇒ 整包不进入写入，回到 F2 提问
写入（按样品分块，逐块独立）
  ├─ 10 → 20 → 30 → 40 → 41 → 50 → 51 → 52 → 60/61/62 → 70/71 → 80 → 90 → A0/A1/A2 → B0
  ├─ 一个样品分块内失败 ⇒ 回滚该分块，其余分块保留（PRD 允许半成品资产）
  └─ 每个分块记录：成功 / 部分成功 / 失败 + 触发的规则ID列表
```

分块独立而非整包原子的理由：PRD §5.3.1 明确「分块独立保存，即时生效」，下游允许读取「基本信息已就绪但无规格或型号明细」的半成品；同时一个标准文件下几十个样品，整包原子会让一个格子的错误废掉全部工作。

## 七、口径已定（原待定项，本轮全部落定）

| # | 事项 | 结论 |
|---|---|---|
| 1 | 试验编码生成规则 | `wz_` + 一级样品分类缩写 +（可续接更下层分类直到样品名称缩写）+ 型号缩写 + 试验项名称缩写；**冲突加 `_2`/`_3`，不用流水号**。见 50 的「试验编码生成规则」与 V05 |
| 2 | 参数编码是否允许人工编制 | **也由系统生成**，基本取参数名称缩写，只读回显。已作为迭代改动写进飞书 Story 第 3 项 |
| 3 | 公式的变量引用语法 | **写参数名称 + 符号，不写编码**（`{导体最大直径|d_max}`），因为 Excel 要给人读。见 80 与 V13 |
| 4 | 判断条件的 If-THEN-ELSE 树 | **要建模**。62_条件规则 加 `分支类型 / 分支序号 / 区 / 连接词` 四列，新增 V10b、V10c |
| 5 | B0 与试验参数内排序谁为准 | **跨类型顺序以 B0 为准**，类型内顺序跟随各自 sheet 的排序列；不一致时 F3 反向同步试验参数 Tab。V22 报错不自动纠正，新增 V23 |
| 6 | 一个包跨多个标准文件 | **一包多任务**，顶层 sheet 加 `任务键` 列；一个任务只处理一份标准文件。见设计原则 6 |

另外两条本轮新增的口径：

- **检测类别不要求必须命中字典**——标准文件里有而字典没有的，允许新增选项，走 C0 确认后落库（V06 已改写）。
- **标称值对比的修饰符与对比符号按单值/非单值分档**：非单值 ⇒ 不配修饰符且只能「符合」；单值 ⇒ 放开 `= != < ≤ > ≥` 且**不得选「符合」**（V19 已改写）。
