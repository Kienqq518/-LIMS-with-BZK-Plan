## 1. Overview

### 1.1 问题陈述

检测中心的管理者、运维和参观客户，今天在"这套系统到底跑得怎么样"上各自拿不到自己要的东西：

- 管理者想知道"现在正不正常、今天出了多少活"，看到的是零散页面和一块不会讲故事的 3D 场景；
- 运维想知道"哪台设备为什么停、谁在处理、处理完没有"，看到的是只有等级色、没有闭环状态的告警点；
- 售前想让客户 30 秒看懂能力，看到的是运行数字，而不是能力叙事。

3D 场景本身已经不是瓶颈（CAD 底座、材质 pass、机器人环线、状态光点、拾取联动都在），**瓶颈是"场景 ↔ 业务"的控制权和口径**：模式（S1/S2/S3）、维度（5M1E）、图层三件事被混在一排按钮里互相覆盖，指标只有"今日"，告警只有"发生"没有"解除"，路径是硬编码推导环线。

### 1.2 方案摘要（一句话）

把 `twin-scene-v2` 从"一个能点的 3D 页面"升级为**一台可以讲、可以看、可以追责的运行大屏**：三格控制层（叙事模式 / 业务切片 / 渲染图层）+ 有口径的 KPI + 有始有终的告警闭环 + 数据可信度四态 + 演示可控（巡航、收起），全部走协议与数据契约，底层是 three.js 还是 Unity 都不返工。

### 1.3 目标用户

| 优先级 | 角色 | 在大屏前的真实动作 | 成功判据 |
|---|---|---|---|
| P0 | 实验室管理者 | 抬头 30 秒判断"正不正常"，异常时点进去看是谁的事 | 异常定位中位耗时 ≤30s |
| P1 | 运维工程师 | 认领告警、回溯发生前后、确认处置 | 每条告警有可核对的闭环链路 |
| P2 | 参观客户 | 站着看 30 秒，听懂"这套系统能做什么" | 讲解人不需要解释"这个按钮是干嘛的" |

## 2. Goals & Success Metrics

### 2.1 目标

1. **看得懂**：任何人 30 秒内说出当前实验室运行状态与这套系统的能力边界。
2. **看得准**：屏上每个数字/状态都有来源系统与刷新口径，断流时诚实降级，绝不装饰性假数据。
3. **追得到**：每条 Grade A/B 告警从触发到解除的链路在大屏上可回溯。
4. **接得上**：三源接入只替换 adapter，前端与协议不动。

### 2.2 左栏数据表口径（2026-11-06 定稿：四张表，报告份数不再展示）

顶栏右上角常驻**时钟**（`YYYY-MM-DD HH:MM:SS 周X`，秒级走动，等宽数字）。左栏保留 **本日 / 本月 / 本年** 切换，四张表随周期联动；每张表表头右侧常显**来源 + 更新时间**（诚实口径从原来的独立胶囊改为进表头）。

| 表 | 行 | 口径与自洽约束 | 来源 |
|---|---|---|---|
| **委托任务** | 委托任务总数；├ 电力电缆类（占比）；└ 安全工器具类（占比） | 两类相加 **=** 总数（本日 14 = 9 + 5） | ② 数采 |
| **样品流转** | 已收样；正在检测（占已收样%）；已完成（占已收样%） | **不再显示「样品总数」**；检测 + 完成 ≤ 已收样（本日 12 + 9 ≤ 23） | ② 数采 |
| **试验项目** | 合计；正在检测；待检测；已完成检测；**未完成中·逾期**；**未完成中·临期(3天内)** | 检测 + 待检 + 完成 **=** 合计（本日 12+9+16=37）；逾期/临期均计入未完成 | ② 数采 |
| **调度任务** | 已完成；阻塞；├ 其中已解决（占阻塞%）；└ 其中未解决（占阻塞%） | 已解决 + 未解决 **=** 阻塞；已完成 + 阻塞 **=** 调度任务总量（本日 88 + 8 = 96） | ① 调度 |

- 每表底部保留同比/环比（▲/▼ + 较上日/上月/年）。
- **逾期 / 临期(3天内) 口径**：来自 **LIMS 的「要求检测完成时间」**（当前 Mock，二期接口接入后自动变真值）。规则：`未完成 且 要求完成时间 < 现在` = 逾期；`未完成 且 0 ≤ 要求完成时间 − 现在 ≤ 72h` = 临期。
  这两项是**现在时指标，不随本日/本月/本年切换变化**（合计/在测/待检/已完成随周期变，逾期与临期保持当前在办口径）。行内带 `LIMS` 角标，hover 可追到具体样品与要求完成时间。
- **假数据也必须可推导**（FR-21）：屏上的逾期/临期/在测/待检/已完成 由 `testItemPlan`（37 条在办清单，每条带 `dueInHours`）现算，不是凭空写的数字——避免现场有人点开明细发现对不上。
- **报告份数整块下线**（原 LIMS 二期口径），来源胶囊里的「LIMS（二期）」同步去掉。
- 契约：`GET /api/overview/lab-status` → `panels{entrust,samples,testItems,dispatch}{title,source,unit,note,periods{day,month,year}{…,compare}}`。
- 演示数据必须**加得起来**：任何人在现场把子项相加都应等于母项，否则视为数据缺陷（已写成自动化断言）。

### 2.3 非目标（沿用 PRD-v1 §6，追加）

- 不做 VR/AR、移动端、多实验室切换、历史深度分析（>24h 回溯）、权限管理。
- **不做深色皮肤/后台控件混入**（参考项目路线已否，见 benchmark §5）。
- 不做孪生对设备/机器人的任何控制下发（安全架构红线）。
- 不做"数据大屏 BI 图表堆砌"——图表只在解释运行状态时出现，不做合格率趋势 top10 那类经营看板（列为 §11 Q6，若做则单独评审为 S4）。

## 4. Scope

### 4.1 In Scope（V1）

三格控制层重构；KPI 口径表与三段切换（数据缺则置灰并标注）；图层体系（path/labels/walls/heatmap/monitor）；告警状态机与派发显示；S3 回溯增强（时间锚 + 事件轴）；S2 卡点视图；演示巡航与面板收起；数据可信度四态在场景内同步显示；协议补齐 ack/超时；诚实降级（未标定不画绝对点位）。

### 4.2 Out of Scope（V1 明确不做）

深色皮肤、Unity/UE 资产替换、LIMS 深链与档案弹卡（二期）、对外分级回放门禁（二期）、经营 BI（S4 候选）、移动端、权限体系、>24h 回溯、真实控制指令。

### 4.3 Future Considerations

- S4 质量检测经营视图：售前价值高但 PRD 未锁 → §11 Q6。

## 5. Solution Design

### 5.1 信息架构：三格控制层【本次更新 · 决策 Q7 定稿】

**5M1E 切片已移除**（原「人/机/料/法/环」五胶囊 + `?v=2` 后删除），S2 不再做成按钮，改为与其余区域一致的**区域下拉框**。现在的三层：

```
① 叙事：[S1 实验室总览] [区域 ▾ 101–110（选中即下钻，106=原 S2 完整视图）] [S3 告警回溯]
② 渲染：图层 icon 组 = 路径 / 场地标签 / 热力（**剖墙已按 2026-11-06 反馈去掉开关**，改为场景固定渲染行为；分区色块此前已移除）
③ 动作：[▾ 收起底栏] [⛶ 全屏（F）]（系统流视图与低配按钮均已移除，低配能力留作 `?quality=low`）
（演示）遥控翻页：← → 或 PgUp/PgDn 走完整序列；1 总览 · 2 无人化区 · 3 告警 · Esc 关闭浮层
```

- FR-1：模式只改叙事与镜头；图层只发 `setLayer`；动作只改浮层/画质。三者互不覆盖，状态持久化到 URL（`?mode=ZONE&zone=106&period=month&layers=path,labels&quality=low`）。
- FR-2：初始加载即应用当前状态（CSS 补 `[hidden]{display:none!important}` 后，隐藏逻辑才真正生效——旧实现里 `display:flex` 覆盖了 `hidden`，切片按钮其实一直没藏住任何东西）。
- FR-2a【本次更新】：底栏内容随叙事切换（S1=今日任务 / 区域 106=调度任务流 / 其他区域=诚实降级说明 / S3=告警时间轴），区域非 106 时机器人卡隐藏、设备看板隐藏并说明原因。
- FR-1a【实现补充】遥控翻页顺序按讲解脚本固定为 **S1 总览 → 106 无人化区 → 101…110 其余区域 → S3 告警回溯**（`PageDown/PageUp`，`1/2/3` 直达；方向键留给三维视角，不与相机打架）。焦点在场景 iframe 内时由桥接层把翻页键 `remote` 消息转回宿主，讲解人不需要先点页面外框。
- FR-1b【实现补充】S3 时底栏让位给回溯抽屉（同一信息不在两处重复渲染）；点告警卡=镜头飞到所属区域（非 106 设备走区域飞行），面板显示闭环状态与「孪生只读」说明。
- FR-1c【实现补充】106 视图的叠层顺序（自上而下）：告警卡（右）→ 设备状态一览 → 机器人卡 → 调度任务流，经 1920×1080 实测无遮挡（看板 bottom:178 / 机器人 bottom:96 / 底栏 bottom:14）。
- FR-1d【实现补充 · 与上游 zone103 合流】设备**区域归属以数据分区为准**（`zoneId` 在装载时按来源分区打戳），因为部分设备的 CAD 模型号落在邻区（如 `2411020108` 借 `cad:107-01` 建模却属 106 分区）；106/103 看板各按归属出卡，无分区数据的区域（101/107…）走诚实降级。`/api/device/{id}/realtime` 查找改为跨分区检索，103 设备同样能取实时参数。上游 V4 IoT 节点协议（`nodes-ready → snapshots` 5s 心跳、`room-selected` 联动）保留并接入新叙事：点场景房间标签=宿主切到该区域下钻（状态与 URL 同步）。
- FR-18【2026-11-06 新增 · 门洞】机器人**只能走门洞进出 106**，禁止在玻璃墙任意位置穿墙：
  1. 实测依据：106 东玻璃墙 x=18.49（z 9.64–28.04 连续），墙上门把手构件 `0x101010 @ x=18.75, z=10.98, y=0.98–1.07`（双开门中缝）→ 门洞中心取 **z=11.0**，跨度取 **z∈[10.2,11.8]**（双扇各约 0.8m）；106 南玻璃墙 z=9.59 无门洞 → 一律禁止穿越；走廊↔102 侧 CAD 未建模墙体，按可通行处理（待现场核实）。
  2. 判定：机器人扫掠方块（半宽 0.651m）与墙面相交时，**必须整块落在门洞跨度内**，否则记违规「穿墙未走门洞」。路线由 A* 在含门洞闸口的墙体障碍上重算，进出各一次、均落在 z=10.99。
  3. 自检：`auditRoutes()` 每次装载按 `walls` 重算；**路线或墙体变化必须重算**（此前只跑首帧，等于没校验——反向注入 z=13 穿墙的坏路径时自检报 0 条，暴露了这一点，已修）。
  4. 可视化：门洞在路径图层内画绿色门槛标记（x≈18.49, z≈11.0），「走门洞」这件事在屏上看得见。
- FR-13【2026-11-06 新增 · 作用范围由 FR-13b 收窄】图层以 icon 呈现且**必须真的生效**：文字标签的 `hidden` 由场景 `render()` 每帧重算，图层开关只能用 CSS 类覆盖，不能用 `visible=false`。
- FR-13b【2026-11-06 修订 · 产品负责人反馈】**「标签」改名「场地标签」，并且只控制各房间名称标签**：
  1. 起因：原实现把「标签」同时当成设备状态光点 + 物联节点名称/类型标签的开关——反馈原话「点击右上角的『标签』控制展示的状态标签是物联节点的名称和物联节点类型，这是不对的」。按钮名和实际作用域不一致，运维会以为关掉标签就没有设备状态。
  2. 现在 `applyLayer('labels')` 只在 `visual.host` 上切 `.no-site-labels`，CSS 只命中 `.room-label`；**设备状态光点（`statusDots`）与物联节点标签（`.orb-tag` / `.node-reading`）不受本开关影响**——前者是告警/状态呈现（FR-3），后者是 IoT 节点层，各自由数据驱动。
  3. 兼容性：图层 key 仍是 `labels`，旧 URL（`layers=path,labels`）与外部链接不变；icon 文案与 `title` 明确「不影响设备状态光点与物联节点标签」。
- FR-13a【2026-11-06 修订】**剖墙不再是图层开关，icon 从 4 个减到 3 个（路径/标签/热力）**。
  墙体剖切（靠近镜头一侧外墙压成 10cm 地脚带 + 玻璃隔断弱化）改为**固定渲染行为**：不剖的话总览会被高墙挡住设备，画面不可读，所以这个"开关"本身没有存在价值——要么常开（有用）要么常关（不可用），没有中间态。
  `restoreWalls()` 与 `LAYERS.walls` 一并删除；旧 URL 里残留的 `walls`/`zones` 参数被忽略且不报错。
- FR-14【2026-11-06 新增】下钻与切近必须是补间动画（§5.9 B/C），且 `prefers-reduced-motion` 下退化为瞬时落位。
  **【回退 · 2026-11-06】** 下钻不再发 `focus-scene`（分组抬升）：该模块会给 `roomIds` 里的每个房间描一圈 `#098bff` 轮廓，
  总览传全部房间＝满屏蓝框（产品负责人反馈「每个房间的蓝线是什么意思」）。现在下钻＝**纯相机补间**

### 5.6 文案规范（双受众，必须分开）

**面向终端用户（大屏可见）**：术语统一为「未解除 / 已派发 / 已解除」「数据延迟」「无实时数据」「未标定，仅显示相对轨迹」「该区 V1 未接入」。禁止出现"mock""stale""missing"等开发词；数字必须带单位与"更新于 hh:mm:ss"。语气：陈述、不指责（写"DL-09 校准已过期，出报告受限"，不写"违规"）。

**面向开发（接口/字段）**：英文小写驼峰 + 状态枚举固定集 `{live,stale,missing,offline}`、`{active,dispatched,resolved}`、`{working,ready,standby,stopped,alarm}`；`null`=未测，`0`=实测零，两者不得混用。

### 5.7 区域视图信息模型（五类 · 产品负责人 2026-11-05 补充定义）

> 原话：**「一个房间区域关注的信息分为 设备、环境数据、任务统计，以及正在运行的任务和告警。」**

### 5.9 浮层与动效规范（2026-11-06 追加）

**A. 透明图表浮层（三处，全部悬在三维画面之上，不做分栏布局）**

| 位置 | 内容 | 视觉 | 滚动 |
|---|---|---|---|
| 左 | 周期切换 + **四张数据表** + 无人化循环进度；数据源胶囊、draw calls 读数、风格预览、避让校验徽标、**告警汇总与筛选**均已按反馈移除或迁走 | `rgba(255,255,255,.55)` + `backdrop-filter:blur(14px) saturate(1.25)` + 1px 白描边 + 柔影 | 内容超高时自身滚动 |
| 右 | **告警流=三个分区各自滚动**：A 异常告警 / B 阻塞·瓶颈告警 / C 校准期限告警（FR-24）。每区头部＝A/B/C 徽标 + 分区名 + `今日 N · 未解除 M` + 本区「只看未解除 / 全部」；流头部一行全局汇总 `今日 N 条 · 未解除 M · 悬停暂停`。列表行 = 标题 / 时刻 / 原因 / 三态 / 区 / 派至 / 详情，**不显示 Grade 英文**。区域视图时整块换成五块区域面板，三个分区改在面板「告警」块内呈现（控件不随表面切换而消失） | 同上玻璃质感 | **每个分区独立连续向上滚动**（外层 `.stream-board` 不滚、区头固定），悬停/聚焦暂停，`prefers-reduced-motion` 停动画 |
| 下 | 今日任务表格（委托单号 / 样品·项目 / 状态 / 设备链 / 进度）——**底部唯一保留的浮层**，机器人状态条与说明条已删除 | 透明底 + 表头细分隔线 + 左右渐隐遮罩 | **连续向上滚动**，同上暂停规则 |

图表一律**现算**：稼动率=在测/已建档；状态分布=当前视图范围（总览算全部建档，区域只算本区）；分级条=未解除告警。禁止装饰性图形（延续 PRD 红线）。

**B. 下钻动效（点房间 → 平滑推近，不再生硬跳视角）**

- 触发：总览页点任意房间标签，或顶栏区域下拉选择。
- 序列（顺序有讲究，写死在实现里）：`camera:begin`（记录切换前构图）→ `focus-scene{roomIds,manualRoom}`（分组抬升）→ `view`（视角切换，**必须排在 focus-scene 之后**，否则被 `resetView` 拉回总览）→ `camera:drill`（补间回落到新构图）。
- 实现要点：`scene-group-highlight` 的 `fitFrame` 每帧重算视锥且不看 `visual.zoom`，因此补间只能在它**之后**按比例缩放视锥；用 `Object.defineProperty(window,'roomTourFrame',{get,set})` 组合，避免后赋值把我方包装顶掉（实测一次性 wrap 会让动画偶发退化成瞬移）。
- 参数：760ms，smoothstep 缓动；`prefers-reduced-motion` 或低配模式 → 瞬时落位（已实测）。
- 结果：画面半高 14.2m → 9.35m 连续推进，800ms 内采到 6 个中间机位；顶栏下拉同步显示该房间名。

**C. 切近动效 + 实体信息卡（任意有信息的实体，含桌子凳子）**

- 触发：点场景内任一 CAD 实体（设备/试验桌/台桌/座椅/货架…）。
- 相机：站到「房间中心 → 实体」连线的反方向（正对操作面），elev 0.62，目标画面半高 ≈ max(2.4m, 实体最大边×1.9)，720ms 补间；实体落在画面 40% 宽 / 52% 高，卡片贴在其右侧。
- 卡片字段：名称（确认名优先）、编号（CAD 号 + 台账编码）、所属区、状态（在测/就绪/待机/异常，非数采对象显示**无实时数据**）、类型或归档状态、分区、关键参数（最多两项）、占地（实测米制）；底部「查看详情与实时参数」→ 宿主右侧详情（3s 轮询）。
- 卡片跟随：每帧按实体世界中心重投影定位；视角变化/点空白/Esc 关闭。
- 诚实约束：非数采对象**不给假状态**，只给 CAD 归档信息与占地（延续 PRD 红线 2）。

**D. 无人化任务循环剧本（让大屏自己动起来）**

- `seed.zone106.robots[RB-C-02].demoCycle`：11 站、76.10m、202.3s 一圈，`t0=停靠开始时刻`，`travelSec` 在其之前；按墙上时钟取模 → 刷新/多人/挂机同相位。
- 顺序=调度任务明细：102 家位/充电 → 102 取料（0142）→ AGV 上料桌（0152）→ 哑铃（0141）→ 径向（0172）→ 热收缩制样（0132）→ 热收缩检测（0131）→ 热延伸（0142）→ 绝缘层厚度（0115）→ 机械性能（0122）→ 检测上下料桌（0121）→ 返航。
- 行走段 `u` 从上一站推进到本站，**停靠段 `u` 不动**（机器人真的停在工位上作业）；末站之后是「返回 102」收尾段，倒计时不出现负数。
- 停靠时对应设备置为「在测」并带上任务号；左栏显示 `n/11 · 停靠作业/行走中 · 剩余 Ns`。
- 路线本身仍受 §10 避让校验约束（5250 采样点 · 73 障碍 · 违规 0）。
- **实现口径**：`u` 是弧长比例，场景按累计长度取位（`posAt`）；有剧本的机器人由**场景内时钟**直接算 `u`，不依赖宿主推送插值；
  动画环单帧异常必须被兜住并留痕（`#twin-v2-loop-error`），否则会出现「机器人不动 + 相机补间失效」且控制台无报错的静默停摆。详见 `animation-spec.md` §12。

## 7. Technical Considerations

### 7.1 约束

- three.js 程序化 CAD 底座不动；场景侧新增消息处理只允许加在 `twin-scene-bridge.js`（V2 专用通道 `twin-v2`），不改 `tour-*` 老页面（其他产品页在用）。
- 场景与宿主通信保持"宿主推、场景显"单向数据流：场景永不直连业务系统。
- 大屏基准 1920×1080，支持 2560/4K；首屏可交互 ≤3s、`scene:ready` ≤5s、帧时 <16.7ms、draw calls 现有 `#perf` 面板可核对。
- 新页面/新子页必须挂 `css/ui-baseline.css` + `js/ui-a11y.js`（已挂，勿删）。

### 7.2 集成点（协议补齐，见 integration 文档升级项）

- 下行新增：`host:setLayer{layer,enabled}`、`host:setAutoRoam{enabled,speed}`、`host:setBottomPanel{collapsed}`、`host:highlight{deviceId|partId}`、`host:jumpTo{areaId|deviceId|waypointId}`；现有 `state`/`view` 保留。
- 上行新增：`scene:waypointClick{waypointId}`、`scene:viewModeChanged`、`scene:stats{fps,frameMs,drawCalls}`（现仅 perf 的 calls/tris）、`scene:error{code,msg,recoverable}`。
- 信封加 `requestId + ack + 3s 超时重试`（参考项目有 requestId 无 ack，是它的缺陷）。
- 【本次更新 · 决策 Q5】调度系统机器人**只直线行走、原地掉头**，不会走弧线。因此路径图层（引导线 + 蓝色环线）必须由工位锚点推导为**直角折线（曼哈顿几何）**：长边先走、再掉头；插值沿折线段进行，转向为瞬时角度切换而非平滑旋转。现场标定前统一标注「相对轨迹」，不显示绝对坐标。
- **已具备、可直接复用**：场景侧 `equipment-highlight` 通道已实现（`whiteblue-spatial-engine.js:30` → `roomTourEquipmentSelection`），宿主只需在点卡片时发一条，**这是 P0 里成本最低、感知最强的一项**。id 空间注意：宿主 `modelNode='cad:106-06'`，发场景须剥掉 `cad:` 前缀。
