## 1. Overview

### 1.1 问题陈述

检测中心的管理者、运维和参观客户，今天在"这套系统到底跑得怎么样"上各自拿不到自己要的东西：

- 管理者想知道"现在正不正常、今天出了多少活"，看到的是零散页面和一块不会讲故事的 3D 场景；
- 运维想知道"哪台设备为什么停、谁在处理、处理完没有"，看到的是只有等级色、没有闭环状态的告警点；
- 售前想让客户 30 秒看懂能力，看到的是运行数字，而不是能力叙事。

3D 场景本身已经不是瓶颈（CAD 底座、材质 pass、机器人环线、状态光点、拾取联动都在），**瓶颈是"场景 ↔ 业务"的控制权和口径**：模式（S1/S2/S3）、维度（5M1E）、图层三件事被混在一排按钮里互相覆盖，指标只有"今日"，告警只有"发生"没有"解除"，路径是硬编码推导环线。

### 1.2 方案摘要（一句话）

把 `twin-scene-v2` 从"一个能点的 3D 页面"升级为**一台可以讲、可以看、可以追责的运行大屏**：三格控制层（叙事模式 / 业务切片 / 渲染图层）+ 有口径的 KPI + 有始有终的告警闭环 + 数据可信度四态 + 演示可控（巡航、收起），全部走协议与数据契约，底层是 three.js 还是 Unity 都不返工。

### 1.3 目标用户

| 优先级 | 角色 | 在大屏前的真实动作 | 成功判据 |
|---|---|---|---|
| P0 | 实验室管理者 | 抬头 30 秒判断"正不正常"，异常时点进去看是谁的事 | 异常定位中位耗时 ≤30s |
| P1 | 运维工程师 | 认领告警、回溯发生前后、确认处置 | 每条告警有可核对的闭环链路 |
| P2 | 参观客户 | 站着看 30 秒，听懂"这套系统能做什么" | 讲解人不需要解释"这个按钮是干嘛的" |

## 2. Goals & Success Metrics

### 2.1 目标

1. **看得懂**：任何人 30 秒内说出当前实验室运行状态与这套系统的能力边界。
2. **看得准**：屏上每个数字/状态都有来源系统与刷新口径，断流时诚实降级，绝不装饰性假数据。
3. **追得到**：每条 Grade A/B 告警从触发到解除的链路在大屏上可回溯。
4. **接得上**：三源接入只替换 adapter，前端与协议不动。

### 2.2 指标口径表【本次更新 · 决策 Q3 定稿：五个都要，默认本日，可切本月/本年】

| 指标 | 来源系统 | 刷新 | 本日 | 本月 | 本年 | 同比/环比 | 实现状态 |
|---|---|---|---|---|---|---|---|
| 委托任务数 | ② 检测数据采控 | 1min | ✅ | ✅ | ✅ | ✅ | mock 已出 |
| 样品支数 | ② 检测数据采控 | 1min | ✅ | ✅ | ✅ | ✅ | mock 已出 |
| 试验项目数 | ② 检测数据采控 | 1min | ✅ | ✅ | ✅ | ✅ | mock 已出 |
| 报告份数 | 应敏 LIMS（二期接入） | 5min | ✅ | **null→置灰** | **null→置灰** | — | 契约已留位，禁止显示 0 |
| 调度任务数 | ① 无人检测调度 | 1min | ✅ | ✅ | ✅ | ✅ | mock 已出 |

> 契约：`GET /api/overview/lab-status` → `periodDefault` + `metricMeta{label,source,refresh,unit,note}` + `metrics{day,month,year}{value,compare}`；`value:null` 与 `0` 语义严格区分（未测 vs 实测零）。每指标右侧常显来源缩写，顶部常显「最近更新 hh:mm:ss」。

### 2.3 非目标（沿用 PRD-v1 §6，追加）

- 不做 VR/AR、移动端、多实验室切换、历史深度分析（>24h 回溯）、权限管理。
- **不做深色皮肤/后台控件混入**（参考项目路线已否，见 benchmark §5）。
- 不做孪生对设备/机器人的任何控制下发（安全架构红线）。
- 不做"数据大屏 BI 图表堆砌"——图表只在解释运行状态时出现，不做合格率趋势 top10 那类经营看板（列为 §11 Q6，若做则单独评审为 S4）。

## 4. Scope

### 4.1 In Scope（V1）

三格控制层重构；KPI 口径表与三段切换（数据缺则置灰并标注）；图层体系（path/labels/walls/heatmap/monitor）；告警状态机与派发显示；S3 回溯增强（时间锚 + 事件轴）；S2 卡点视图；演示巡航与面板收起；数据可信度四态在场景内同步显示；协议补齐 ack/超时；诚实降级（未标定不画绝对点位）。

### 4.2 Out of Scope（V1 明确不做）

深色皮肤、Unity/UE 资产替换、LIMS 深链与档案弹卡（二期）、对外分级回放门禁（二期）、经营 BI（S4 候选）、移动端、权限体系、>24h 回溯、真实控制指令。

### 4.3 Future Considerations

- S4 质量检测经营视图：售前价值高但 PRD 未锁 → §11 Q6。
- 人员在场（Man 维度）：需要定位/门禁数据源，V1 只用"排班+工位绑定"弱表达 → Q7。
- 相机视频位与安防联动：等 ③ 物联接口口径确定 → Q5。

## 5. Solution Design

### 5.1 信息架构：三格控制层【本次更新 · 决策 Q7 定稿】

**5M1E 切片已移除**（原「人/机/料/法/环」五胶囊 + `?v=2` 后删除），S2 不再做成按钮，改为与其余区域一致的**区域下拉框**。现在的三层：

```
① 叙事：[S1 实验室总览] [区域 ▾ 101–110（选中即下钻，106=原 S2 完整视图）] [S3 告警回溯]
② 渲染：[≡ 图层] = 调度路径 / 设备状态标签 / 分区色块 / 墙体剖切 / 工位负荷热力
③ 动作：[⇄ 系统流] [▾ 收起底栏] [低配]
（演示）遥控翻页：← → 或 PgUp/PgDn 走完整序列；1 总览 · 2 无人化区 · 3 告警 · Esc 关闭浮层
```

- FR-1：模式只改叙事与镜头；图层只发 `setLayer`；动作只改浮层/画质。三者互不覆盖，状态持久化到 URL（`?mode=ZONE&zone=106&period=month&layers=path,labels&quality=low`）。
- FR-2：初始加载即应用当前状态（CSS 补 `[hidden]{display:none!important}` 后，隐藏逻辑才真正生效——旧实现里 `display:flex` 覆盖了 `hidden`，切片按钮其实一直没藏住任何东西）。
- FR-2a【本次更新】：底栏内容随叙事切换（S1=今日任务 / 区域 106=调度任务流 / 其他区域=诚实降级说明 / S3=告警时间轴），区域非 106 时机器人卡隐藏、设备看板隐藏并说明原因。
- FR-1a【实现补充】遥控翻页顺序按讲解脚本固定为 **S1 总览 → 106 无人化区 → 101…110 其余区域 → S3 告警回溯**（`PageDown/PageUp`，`1/2/3` 直达；方向键留给三维视角，不与相机打架）。焦点在场景 iframe 内时由桥接层把翻页键 `remote` 消息转回宿主，讲解人不需要先点页面外框。
- FR-1b【实现补充】S3 时底栏让位给回溯抽屉（同一信息不在两处重复渲染）；点告警卡=镜头飞到所属区域（非 106 设备走区域飞行），面板显示闭环状态与「孪生只读」说明。
- FR-1c【实现补充】106 视图的叠层顺序（自上而下）：告警卡（右）→ 设备状态一览 → 机器人卡 → 调度任务流，经 1920×1080 实测无遮挡（看板 bottom:178 / 机器人 bottom:96 / 底栏 bottom:14）。
- FR-1d【实现补充 · 与上游 zone103 合流】设备**区域归属以数据分区为准**（`zoneId` 在装载时按来源分区打戳），因为部分设备的 CAD 模型号落在邻区（如 `2411020108` 借 `cad:107-01` 建模却属 106 分区）；106/103 看板各按归属出卡，无分区数据的区域（101/107…）走诚实降级。`/api/device/{id}/realtime` 查找改为跨分区检索，103 设备同样能取实时参数。上游 V4 IoT 节点协议（`nodes-ready → snapshots` 5s 心跳、`room-selected` 联动）保留并接入新叙事：点场景房间标签=宿主切到该区域下钻（状态与 URL 同步）。
- FR-2b【本次更新 · 决策 Q6】：S1 不加能力叙事层（不做试验项目/精度等级/案例墙），只做运行镜像。

### 5.3 核心用户动线（P0 主流程 + 两条异常分支）

```mermaid
flowchart TD
    A[大屏待机 / 巡航中] --> B{Grade A 或 B 告警触发}
    B -->|巡航中| C[立即暂停巡航 · 镜头飞向设备]
    B -->|有人操作| D[右侧告警卡入列 · 设备红脉冲]
    C --> E[运维点卡 → 详情面板 + 实时参数轮询]
    D --> E
    E --> F{能定位原因?}
    F -->|能| G[S3 回溯：前后5min事件轴 → 标记处置中]
    F -->|不能| H[调阅工位/监控点位或电话上报<br/>孪生侧只记录"升级至人工"]
    G --> I{处置结果回传}
    I -->|已解除| J[卡转绿 · 计数入"已解除" · 保留时间锚]
    I -->|断流未回| K[置 stale：卡变灰 + 显示"数据延迟 · 最后 08:12"]
    K --> L[顶部数据源胶囊变黄 · 不隐藏卡片]
```

### 5.4 告警闭环状态机（吸收参考项目，去掉它的后台控件混入）

```
触发 → 自动处置(可自动的规则) → 派发(人/终端) → 复核 → 已解除
                                     ↓ 超时未响应 → 升级（上一级派发对象）
```

| 状态 | 显示 | 可点动作 | 数据来源 |
|---|---|---|---|
| `active` 未解除 | 红/橙/琥珀实心 + 场景脉冲 | 回溯、查看派发对象 | 判定规则 / ② |
| `dispatched` 已派发 | 同色 + 「派至 X · hh:mm」 | 仅「回溯」 | ① / ② / 判定规则经网关推送（**决策 Q2：孪生不写回**） |
| `resolved` 已解除 | 绿描边、**不再脉冲**、留卡 30min | 回溯 | 处置系统 |
| `stale` 数据延迟 | 变灰 + 最后更新时间 | 提示刷新 | 新鲜度判定 |

- FR-3：Grade A/B 在场景内必须显示状态差异（`resolved` 设备停止红脉冲）；判据由 `status!=='resolved'` 驱动。
- FR-3a【本次更新 · 决策 Q2】：**孪生只读，取消写回**。原 `安灯呼叫` 按钮与 `TwinApi.alarmAck()` 已删除，卡片只保留「回溯」；屏上**不出现**「演示回执」等标注，闭环状态（active/dispatched/resolved）一律由来源系统经网关推送。
- FR-4：同屏脉冲对象 ≤3（超出则按等级择优，其余显示静态红点）。这是既有验收红线，需在前端实现而非只在文档里写。
- FR-5：派发矩阵与升级超时值为配置项（`data/andon-routing.json`），不得写死在 JS。

### 5.6 文案规范（双受众，必须分开）

**面向终端用户（大屏可见）**：术语统一为「未解除 / 已派发 / 已解除」「数据延迟」「无实时数据」「未标定，仅显示相对轨迹」「该区 V1 未接入」。禁止出现"mock""stale""missing"等开发词；数字必须带单位与"更新于 hh:mm:ss"。语气：陈述、不指责（写"DL-09 校准已过期，出报告受限"，不写"违规"）。

**面向开发（接口/字段）**：英文小写驼峰 + 状态枚举固定集 `{live,stale,missing,offline}`、`{active,dispatched,resolved}`、`{working,ready,standby,stopped,alarm}`；`null`=未测，`0`=实测零，两者不得混用。

### 5.7 数据规范（新增/补齐字段，落到 `twin/api/seed.json` + 契约）

| 对象 | 新增字段 | 类型/枚举 | 说明 |
|---|---|---|---|
| Alarm | `status` | `active\|dispatched\|resolved` | 现为单值 active |
| Alarm | `dispatchedTo`, `dispatchedAt`, `resolvedAt` | string / ISO / ISO | 闭环链路 |
| Alarm | `source` | `daq\|dispatch\|iot\|rule` | 来源系统标签（参考项目要求） |

## 7. Technical Considerations

### 7.1 约束

- three.js 程序化 CAD 底座不动；场景侧新增消息处理只允许加在 `twin-scene-bridge.js`（V2 专用通道 `twin-v2`），不改 `tour-*` 老页面（其他产品页在用）。
- 场景与宿主通信保持"宿主推、场景显"单向数据流：场景永不直连业务系统。
- 大屏基准 1920×1080，支持 2560/4K；首屏可交互 ≤3s、`scene:ready` ≤5s、帧时 <16.7ms、draw calls 现有 `#perf` 面板可核对。
- 新页面/新子页必须挂 `css/ui-baseline.css` + `js/ui-a11y.js`（已挂，勿删）。

### 7.2 集成点（协议补齐，见 integration 文档升级项）

- 下行新增：`host:setLayer{layer,enabled}`、`host:setAutoRoam{enabled,speed}`、`host:setBottomPanel{collapsed}`、`host:highlight{deviceId|partId}`、`host:jumpTo{areaId|deviceId|waypointId}`；现有 `state`/`view` 保留。
- 上行新增：`scene:waypointClick{waypointId}`、`scene:viewModeChanged`、`scene:stats{fps,frameMs,drawCalls}`（现仅 perf 的 calls/tris）、`scene:error{code,msg,recoverable}`。
- 信封加 `requestId + ack + 3s 超时重试`（参考项目有 requestId 无 ack，是它的缺陷）。
- 【本次更新 · 决策 Q5】调度系统机器人**只直线行走、原地掉头**，不会走弧线。因此路径图层（引导线 + 蓝色环线）必须由工位锚点推导为**直角折线（曼哈顿几何）**：长边先走、再掉头；插值沿折线段进行，转向为瞬时角度切换而非平滑旋转。现场标定前统一标注「相对轨迹」，不显示绝对坐标。
- **已具备、可直接复用**：场景侧 `equipment-highlight` 通道已实现（`whiteblue-spatial-engine.js:30` → `roomTourEquipmentSelection`），宿主只需在点卡片时发一条，**这是 P0 里成本最低、感知最强的一项**。id 空间注意：宿主 `modelNode='cad:106-06'`，发场景须剥掉 `cad:` 前缀。
