## 一、这份契约要解决什么

三段之间只靠一个东西传递信息：**这份 Excel**。它必须同时满足两个互相拉扯的要求——

- **人能读懂**：专家在 F2 要能扫一眼就找到该改的格子，不会因为在跟一个序列化格式搏斗而放弃复核。
- **机器能校验后入库不报错**：F3 要能在写入前把真实系统的全部强校验（试验编码大类内绝对唯一、参数名称单样品内唯一、符号不冲突、标称值被判定引用不可删、区分型号一旦挂型号不可关闭……）全部预演一遍，而不是写一半炸掉。

所以契约不是「把 Word 里的表格原样搬进 sheet」，而是**把抽屉的数据模型摊平成行列**。附件1-4 里 115 张表按语义归并到 22 张 sheet，一张 sheet 对应抽屉里的一个实体层级。

## 二、七条设计原则

1. **sheet-per-entity，不是 sheet-per-table。** 一行 = 一个实体实例（一个样品 / 一个试验项 / 一条标称值 / 一行映射数据）。
2. **稳定业务主键，绝不用行号当外键。** 专家在 F2 会排序、筛选、删行、线下改完传回来，行号一定会变。父子之间只靠 key 列关联。
3. **表头固定在第 1 行，禁止合并单元格。** Word 里的合并单元格在转换时展开成重复值 + 一个 `分组` 列，避免解析歧义。
4. **值与元数据分离。** 每个由 AI 产出的字段，其置信度记在 `C0_待定项`，不污染数据列本身；F2 的着色靠这张表驱动。
5. **导入顺序 = 拓扑顺序。** sheet 名前缀 `00/10/…/D0` 就是导入次序；前置实体缺失即整包拦截，不允许静默跳过留下半成品。
6. **一个 .xlsx 可含多个任务，一个任务只处理一份标准文件。** 客户能力范围常覆盖十几份标准，拆成十几个文件会把 F2 的复核切碎。所有顶层 sheet 带 `任务键`（= 标准文件编号）列，`10_分类路径` 起就按任务分组；定稿与入库仍以「任务 → 样品分块」为单位推进。
7. **契约必须能吃「不是 F1 生成的包」。** 附件1-4 那四份人工 Word 拆解稿转成的 Excel，要能直接进 F2/F3——这是契约通用性的验收用例。

**AI 分级**（贯穿所有 sheet 的一列语义）：

| 级 | 含义 | 典型字段 |
|---|---|---|
| **A 自动** | 有权威来源可直接核对 | 样品名称、标准号、试验名称、单位、测量次数 |

| **C 必须问人** | 输入文件里根本不存在，只能问 | 检测类别、映射类型、修约方式、判定模式、判断层级、是否覆盖 |

**标准文件为什么会出现在分类树的中间层**（口径已定，以 DL/T 802 为例）：

```
BHG 电缆保护管            ← 样品类别：一种"大类样品"，下面有很多种导管
└─ DL/T 802.1—2023         ← 标准文件节点（总则标准）：列举有哪些类型，并指向各自的标准
   └─ 实壁类塑料电缆导管     ← 更细一层样品类别
      └─ DL/T 802.3—2023    ← 标准文件节点（明细标准）：这一类的技术要求与试验方法
```

- 标准节点挂在**对应那一层样品分类下**，不是统一挂顶层：同一层可能并列多个年份版本的标准节点，标准更新时同级新增、旧节点保留，历史委托才能溯源。
- 某一类导管没有独立标准时就不需要标准节点，直接挂在 802.1 下面。
- 所以「哪一段是标准节点、它是总则还是明细、指向哪些子标准」**只能从上传的标准文件正文读出来**。DS 那份 Word 的第一张表「引用标准文件清单」（标准编号 / 标准名称 / 用途）正好承载这件事——用途列已经写了"主标准文件""通用技术要求（尺寸表3/4）及通用试验方法"，映射到 `标准层级角色` 与 `指向的标准文件编号`。

**任务发现（F1 的范围级动作，口径已定）**：用户只上传总则标准（802.1），而 F1 从正文判断出各类型导管各有自己的明细标准时——

1. 先告知客户「本能力范围内需按不同标准文件各自拆解任务，预计 N 个」并列出这 N 个编号。**N 一定落在客户检测能力范围之内**，超出能力范围的类型不生成任务。
2. 标准文件库按编号+年号查不到的那些明细标准，要求客户上传；上传即入库，元数据全局共享。
3. 客户不上传也能继续，但只能拆到总则标准覆盖的通用要求为止，缺的部分在 C0 标成「未验证」，**不允许当作定稿**。

> 校验 **V01**：每个样品必须能在本 sheet 里找到一条 `节点类型=标准文件` 的祖先，否则按 PRD 阻断新增样品。
> 校验 **V01b**：`标准层级角色=总则标准` 且 `指向的标准文件编号` 非空 ⇒ 被指向的每个编号要么已存在于本包或标准文件库，要么在 C0 挂着一条「请上传该标准文件」的**范围级**问题。

| 例 | 拆解 |
|---|---|
| `wz_dldl_lhjx_insul` | wz + dldl（电力电缆类）+ lhjx_insul（老化前绝缘的机械性能试验） |

**跳过口径（本轮拍板）**：允许人「跳过」任何一条问题，跳过 = **延迟决策**，不是"按默认值"也不是"不拆了"。

| 阶段 | 行为 |
|---|---|
| F1 / F2 跳过 | 该条数据先按 AI 当前最优猜测占位（`处置状态=已跳过`，稿件里标灰），**不阻塞生成稿件**，也不阻塞定稿 |
| F3 预检 | 所有 `已跳过` 条目**必须再问一次**，集中成「跳过项二次确认」清单，逐条给出「AI 会选什么 + 依据」。V24 挡住：还有未二次处置的跳过项 ⇒ 不得入库 |

范围级问题同样允许跳过，但界面要更重地提示：跳过等于把「拆成什么结构」交给 AI，影响面是整块数据而不是一格。
`已忽略` 只给内部档用（工程侧确认这条问题本身不成立），客户档不暴露，避免变成"绕过校验"的后门。

## 五、F3 导入的事务边界

按之前定的：**任务边界 = 标准文件，定稿与入库挂在样品分块上**。

```
预检（整包，只读）
  ├─ 跑 D0 全部规则，产出「预检报告」，不写库
  └─ 有阻断项 ⇒ 整包不进入写入，回到 F2 提问
写入（按样品分块，逐块独立）
  ├─ 10 → 20 → 30 → 40 → 41 → 50 → 51 → 52 → 60/61/62 → 70/71 → 80 → 90 → A0/A1/A2 → B0
  ├─ 一个样品分块内失败 ⇒ 回滚该分块，其余分块保留（PRD 允许半成品资产）
  └─ 每个分块记录：成功 / 部分成功 / 失败 + 触发的规则ID列表
```

分块独立而非整包原子的理由：PRD §5.3.1 明确「分块独立保存，即时生效」，下游允许读取「基本信息已就绪但无规格或型号明细」的半成品；同时一个标准文件下几十个样品，整包原子会让一个格子的错误废掉全部工作。

另外两条本轮新增的口径：

- **检测类别不要求必须命中字典**——标准文件里有而字典没有的，允许新增选项，走 C0 确认后落库（V06 已改写）。
