# 品类规则绑定设计（Category-Rule Binding）

飞书文档：`NmYVdjPO9oswaoxyHsDcQNu2nKh`｜台账 Base：`B2WHb25XVaCPinskfxKcr0J0npt`

## 背景

用户观察 3.2.1 的 A03 质控规则后发现：**同一规则在不同检测样品上取值不同**（扭矩系数每批 8 套 / 拉伸每批 2 根 / 绝缘手套逐只 / 金具握着力 3 件），规则应与样品绑定。现状是 45 条规则全局生效，台账只有「适用领域」三值（电网物资 / 安全工器具 / 通用），粒度过粗；代码 `BaseRule.applicable_domains` 与 `ai_review_rules.applicable_domains` 只到"领域"级。

本设计把"规则本体"与"品类绑定"分离，使规则可按品类差异化生效，同时避免每品类复制规则导致的维护失控。

## 范围（已确认）

| 项 | 决策 |
| --- | --- |
| 绑定模型 | **B**：规则本体不变 + 新增品类规则绑定表（多对多） |
| 品类字典来源 | **①** LIMS 已有的物料 / 样品分类字段（做镜像，不直接依赖外部枚举） |
| 未配置品类的默认策略 | **①** 只跑通用规则集 + 输出一条「该品类未配置专属规则」提示；不全量跑、不静默跳过 |
| 首批品类与批次 | 6 个品类全部建镜像记录；**M1 只配 3 个绑定**（高强度螺栓连接副、绝缘手套、电力电缆），其余 3 个（电缆保护管、安全带、导线/金具）走默认策略，M2 前两周补齐 |
| 绑定表能否凭空造规则 | **不能**。品类专属规则必须先进本体表，绑定表只决定"跑不跑 + 参数 + 依据 + 严重度覆盖" |
| 参数数值可信度 | 全部标 `状态=待审核员确认`，由 Week 1 Day 3–4 领域顾问校准 |

## 数据模型

**1. `ai_review_rules`（本体，45 条）变更**
- 新增 `param_schema JSONB`：声明该规则可覆盖的参数与类型，如 `{"parallel_count":"int","cycle_months":"int","leak_limit_ref":"enum"}`
- 新增 `is_universal BOOLEAN`：是否属于通用集（见下）
- `applicable_domains` 保留但降级为粗筛兼容字段；**判定式内不得出现品类专属数值**（8 套、6 个月等一律移入绑定表）

**2. 新增 `ai_review_categories`（品类字典镜像）**
`category_code` PK｜`category_name`（快照名）｜`source`（默认 LIMS）｜`lims_parent_code`（支持前缀匹配）｜`sync_time`｜`enabled`
> 镜像而非直连：LIMS 改名 / 并码时绑定表不崩，且能显式发现"分类粒度不匹配"。

**3. 新增 `ai_review_category_bindings`（品类规则绑定）**
`binding_id` PK｜`category_code` FK｜`rule_id` FK｜`enabled BOOLEAN`｜`overrides JSONB`｜`severity_override VARCHAR(20) NULL`｜`standard_ref VARCHAR(200)`｜`version`｜`effective_from`｜`effective_to`｜`approved_by`｜`change_ticket`
唯一约束 `(category_code, rule_id, version)`；索引 `(category_code, enabled)`。变更控制复用 3.8 同一套字段与流程。

## 通用集定义（31 条）

与品类无关、任何报告都跑：A01-1…6（6）、A02-1…5（5）、A03-1 校准证书（1）、B01-1/2/4/5（4）、B03-1…4（4）、C01-1…5（5）、C02-1…5（5）= **30**。

品类专属（**15**，必须由绑定表启用）：A03-2 平行组数、A03-3 试样根数、**A03-4 炉（批）号与取样部位**、A03-5 CRM 核查、A03-6 超差复检、B01-3 预防性试验周期、B02-1…9（强度自洽 / 伸长率 / 扭矩系数 / 预拉力 / 硬度换算 / 耐压泄漏 / 镀层尺寸 / 加载速率 / 公式验算）= **15**。30 + 15 = 45 ✓

> **A03-4 归入专属侧的理由**：「炉（批）号」是钢材 / 金具类概念，电力电缆没有炉批号，其可追溯载体是**盘号 / 制造批号 / 段号**。因此 A03-4 的判据本身也要参数化——`param_schema` 增加 `traceability_field: enum(heat_no | reel_no | batch_no | segment_no)`，由绑定表按品类指定，而不是假定所有样品都有炉批号。

> **通用 ≠ 无参数。** 通用只表示「任何品类都跑」；通用规则同样可以有品类覆盖参数——如 A02-5 的敏感项目清单、C01-2 的修约间隔、C01-4 的单位集合。区分的是**是否需要绑定才启用**，不是有没有参数。

## 运行时解析

输入 `report_data.sample_info.category_code`：
1. 查 `ai_review_categories`（精确码 → 前缀 `lims_parent_code` 匹配 → 未登记）
2. 命中且有绑定：取 `enabled=true` 行，`overrides` 合并进 `context`，`severity_override` 覆盖默认严重度
3. 命中但无绑定 / 未登记品类：**只取通用集 30 条**，并生成提示 `CAT-UNCAT-01`「该品类未配置专属规则，仅执行通用检查」，严重度 = 提示，不阻断签发

> `CAT-UNCAT-01` 是引擎内置提示，**不占本体规则编号**，不计入 45 / ≥50 的条数统计。
4. `BaseRule.is_applicable()` 改为**品类优先、领域兜底**；新增参数注入 `context["overrides"]`
