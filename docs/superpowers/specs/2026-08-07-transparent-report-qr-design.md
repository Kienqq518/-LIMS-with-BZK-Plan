## 0. 一句话结论

先搭「**报告级溯源二维码 + 八维度信息聚合器 + 分级公开引擎**」这套骨架，用现有数据即可**真实出具三级（可追溯）/ 四级（可公示）**报告；**一级 / 二级**先建模、页面预留占位，随后按「过程影像、环境监测、设备自动采集、人员资质、数据存证」等**可插拔模块**逐个接入后**解锁**。这与老板「框架先搭、能力不足处后续补模块」的思路完全一致。

> 结合飞书《透明检测理念》与实际对接现状：环境/影像等物联数据由 **组态物联终端**（公司另一款产品，其组态物联节点亦可为试验采集环境数据）提供，LIMS **经数采系统**对接（见 §1.4、§10）。**温湿度自动采集链路已打通**（可在第一阶段直接用于「环」维度，含后续连续型温湿度）；**视频节点**硬件即将就绪，可同步纳入设计。因此这些维度模块是**经数采系统对接组态物联终端的采集适配器**，而非全部自建。
>
> 术语约定：透明检测语境下统一称 **「组态物联终端」**，不使用产品名「安全管家」。

## 1. 背景与目标

### 1.1 标准核心逻辑（来自 Q/YM 006—2026）

- **一报告一码**：报告首页印刷唯一溯源二维码，与本次检测终身绑定、不可复用、不可篡改；扫码查看**对应等级下**的公开内容。
- **报告等级 = 实验室能力等级**：出具何种等级的透明报告，即代表实验室对应的透明运行与数据防篡改能力。
- **双核心评级**：以「①二维码信息公开完整度 + ②数据流转自动化程度」为双核心，由高到低分四级。
- **八大维度**：人、机、料、法、环、试验流程、过程影像、**数据流转**（新增核心维度：人员干预越少、自动流转越高、篡改概率越低，等级越高）。
- **等级前置选定**：实验室在检测前按客户需求选定本次报告等级，选定后必须严格执行对应等级要求，严禁降级出具。

### 1.2 本项目目标

1. 在报告链路中集成「报告级」唯一溯源二维码，扫码进入**分级公开页**，展示本次检测的八维度信息。
2. 建立四级透明度等级模型与「等级 ↔ 公开内容」的严格锁定（后台按等级控制展示）。
3. 搭建**八维度信息聚合器**：从现有各模块自动归集数据，缺失维度显式标注「暂未采集/该等级不公开」。
4. **框架优先**：先支撑现实可达的三/四级完整闭环；一/二级预留，能力模块逐步补齐后解锁。

### 1.4 理念要点 + 组态物联终端对接现状

**飞书《透明检测理念》要点**（标准之上的理念与价值）：

- **理念**：从「结果交付」升级为「**过程交付**」，把检测「黑箱」变「玻璃房」，实现「**检测即所见**」；「一报一码」是实验室诚信与能力的「数字身份证」。
- **价值三层**：对客户（远程审计、降低决策风险）、对实验室（招投标差异化，不再单拼价格）、对行业（从「人防/制度防」转向「**技防/物联防**」）。
- **技术底座 = 组态物联终端**（公司另一款产品；其组态物联节点亦可为试验采集环境数据）+ **数采系统** + **上位机** + **LIMS** 的协同，物联数据自动上报、减少人工干预、天然防篡改。

> 术语：透明检测语境下统一称 **「组态物联终端」**，不使用产品名「安全管家」。

**实际对接现状（重要，据附件流程图）**：LIMS 不直接连组态物联终端，而是**经数采系统中转**。当前已打通的能力：

1. **预配置**：组态物联终端侧完成三方集成（设置数采回调地址、下发设备编号与 API Key）；数采系统绑定设备（设备编号 + API Key）、绑定试验项（绑试验设备、绑试验检验点/字段、关联节点类型）。
2. **试验过程**：LIMS 下发采集任务 → 数采系统接收；上位机拉取试验任务并做**物模型绑定（特殊，仅一次，点选具体物联节点）**；上位机按任务向数采请求数据 → 数采向组态物联终端取数 → 组态物联终端接口响应**返回温湿度数值**；无在线数据时可**手输**兜底。
3. **数据流转**：试验结束上报试验数据，温湿度数据**由数采回传 LIMS**，用于本次报告的「环」维度，最终完成报告。

```
组态物联终端                数采系统                上位机                 LIMS
    │(预配置:回调地址/编号/APIKey)│                       │
    │───────────────────────────►│ 绑定设备/试验项        │
    │                            │                       │◄──下发采集任务──┐(接收任务)
    │                            │◄──接收任务────────────│                │
    │                            │                       │ 拉取试验任务 ◄─┘
    │                            │                       │ 物模型绑定(仅一次,点选节点)
    │◄──取温湿度──── 请求数据 ◄──┤◄──获取温湿度──────────│
    │──接口响应:温湿度数值──────►│──────────────────────►│ 有在线数据? 否→手输
    │                            │◄──收到数据──试验结束上报│ 是→上报
    │                            │────温湿度回传 LIMS────────────────────► 完成报告
```

**当前能力边界与规划**：
- ✅ **温湿度数据获取已完成**（单点/时点值），可在**第一阶段**直接用于「环」维度自动采集；
- 🔜 **连续型温湿度**（全过程曲线）后续可完成 → **纳入第一阶段设计**（数据模型与公开页先支持曲线）；
- 🔜 **视频节点采集**硬件即将就绪 → **设计时同步纳入**过程影像（先预留数据结构与公开位，硬件到位即接）。

**对本方案的含义**：§10 高阶维度中，「环（温湿度）」已具备**真实自动采集**（经数采系统），不再只是人工录入过渡；「过程影像（视频）」可提前设计。LIMS 侧适配器职责 = 「下发采集任务 / 消费数采回传 → 归一化为维度快照」，物联硬件与原始采集由组态物联终端 + 数采系统承接。

### 1.5 老板意图（框架先搭）

> 「框架先搭出来，系统基础能力不行的地方后续再慢慢增加模块功能，比如人员资质管理等这些我们目前都没有。」

设计原则据此定为：**骨架稳定 + 维度可插拔 + 等级按能力解锁**。骨架（二维码、聚合器、公开页、等级引擎、存证接口）一次搭好且不随维度增减变动；每个维度是一个**采集适配器（Adapter）**，缺失时降级为占位，补齐后即插即用，不改骨架。

## 2. 与现有「合格证短链」的关系（重要边界）

系统已有一条**样品级**溯源线：合格证短链（`short-link-qr.js` + `cert-verify.html`），用于「某个样品是否合格、是否在有效期内」。本方案是**另一条平行的报告级**溯源线，二者**不可混用**：

| 维度 | 现有：合格证短链 | 本方案：报告溯源二维码 |
|------|------------------|------------------------|
| 绑定对象 | 单个**样品**（sample_no） | 整份**报告**（report_no / 本次检测全要素） |
| 载体位置 | 合格证 / 样品标签 | **报告首页显著位置** |
| 扫码内容 | 合格与否、再检日期 | 八维度信息，**按透明度等级分级公开** |
| 核心诉求 | 防伪、有效期核验 | 透明度分级 + 数据防篡改能力展示 |
| 状态规则 | valid/expired/revoked（签发后发码、回退作废） | 报告签发后生成、终身绑定、不可复用；报告作废/召回联动 |

**复用策略**：短链跳转基建（`/l/{code}` → 302 → 公开 H5、内网/公网 Base 切换、本地 QR 生成、局域网/公网三种部署方案）可**直接复用**，无需重建；仅新增「报告级」的 code 命名空间、映射表与公开页。建议报告码前缀区分（如 `R` 段），避免与合格证码混淆。

## 3. 现有能力盘点 × 八维度差距分析

> 结论：三/四级所需信息**现网基本齐备**；一/二级所需的**实时影像、环境监测、设备自动采集、人员资质、强制防篡改**属于当前缺失能力。

| 维度 | 标准高阶要求 | 现网已具备 | 现网缺口（→ 后续模块） | 三/四级可达 |
|------|--------------|------------|------------------------|:-----------:|
| **人** | 姓名、资质证书、操作授权、培训考核；不接触原始数据 | 检测员选择（`inspector-select.js`）、角色管理（`testos-role-mgmt`）、当前用户 | **人员资质管理**（证书/授权/培训考核） | ✅（仅姓名/编号） |
| **机** | 编号、校准证书、维护记录、**实时运行参数曲线**、自动采集 | 设备管理：编号、校准状态、下次校准、证书编号、校准机构、校准报告、维护事件历史（`equip-mgmt.html`） | 设备**实时参数曲线**、**自动采集**（→ 经数采系统对接组态物联终端） | ✅（编号+校准证书） |
| **料** | 来源、编号、全流程自动流转、耗材合格证明/批次 | 样品管理全流程（收样/制备/发样/还样/退样）编号、流转、时间、责任人 | **耗材管理**（合格证明/批次自动记录） | ✅（样品编号+关键流转节点） |
| **法** | 执行标准全文、作业指导书、算法固化自动计算、人工不可改逻辑 | 标准管理（`standard-mgmt.html`）、判定规则、报告判定 | **作业指导书**（占位）、计算逻辑固化程度 | ✅（标准编号+原始数据摘要） |
| **环** | 全过程温湿度实时曲线、环境布局、安全环保、自动上传 | **温湿度自动采集已打通**（LIMS 下发任务 → 数采系统 → 组态物联终端温湿度节点 → 回传），无在线数据可手输兜底 | **连续型温湿度曲线**（后续，已纳入一期设计）、环境布局/烟雾等其他节点 | ✅ **三级「平均温湿度」自动采集即可达**（四级不公开） |
| **试验流程** | 委托—收样—制样—检测—复核—报告全节点时间/责任人自动留痕 | 全流程节点建模（`flow-stages.js`）、各环节时间/责任人 | 节点留痕的**自动化与完整度** | ✅（核心节点） |
| **过程影像** | 关键节点照片 / 关键环节视频 / 全程连续视频 / 实时监控 | 无 | **照片**（各流程环节即拍即传，LIMS 轻量上传）；**视频节点硬件即将就绪**（组态物联终端视觉节点，凭时间锚回源，见 §5.1） | ⚠️ 三级需 2–5 张关键照片——各环节上传即可；四级无需 |
| **数据流转** | 采集→传输→存储→计算→复核→生成全自动、人员不可篡改、全程留痕 | 试验检测**以人工录入为主**（`test-detect-edit.html`）；**温湿度已走自动采集回传**；数据审核（`data-audit.html`）、操作日志 | **更多环节自动采集/计算闭环**、**强制防篡改存证**（哈希/TSA/链）、修改留痕强化 | ✅（三级=人工+温湿度自动+修改留痕；四级=简单存储） |

**能力小结**
- 现在就能达标的维度：人（姓名/编号）、机（校准证书）、料（样品流转）、法（标准编号）、试验流程（核心节点）、数据流转（三/四级形态）、**环（温湿度自动采集已打通）**。
- 需最小补齐才能达三级的：**过程影像（关键照片，LIMS 轻量上传）** —— 三级要求，四级不要求。（环的温湿度已可自动获取。）
- 需要专门能力方可迈向二/一级的：过程影像（视频/监控，硬件将就绪）、连续型温湿度曲线、设备运行参数自动采集、人员资质、耗材、数据自动闭环 + 强制防篡改。

## 4. 四级等级可达性评估

| 等级 | 名称 | 二维码公开总要求 | 依赖能力 | 当前可达性 |
|:----:|------|------------------|----------|-----------|
| 四级 | 可公示 | 最低合规信息，无影像 | 现网数据即可 | ✅ **现在可出具** |
| 三级 | 可追溯 | 八维度核心信息 + 2–5 张关键照片，无视频；有修改留痕 | 平均温湿度（**已自动采集**）+ **关键照片上传**（唯一待补）+ 修改留痕 | ✅ **补关键照片上传即可出具** |
| 二级 | 可视化 | 八维度完整 + 关键节点视频；高自动化，仅少量人工复核 | 需视频采集（**硬件将就绪**）、设备运行参数自动采集、数据自动流转 | ⛔ 预留，视频硬件到位后临门 |
| 一级 | 全要素 | 100% 完整 + 全程连续视频 + 实时监控；全自动闭环，人员不可篡改 | 需无人化试验、全链路自动、强制防篡改存证 | ⛔ 预留，待模块接入解锁 |

**产品策略（对应标准 §9）**：一/二级为核心竞争力（国央企/电网/招投标），三级面向普通市场化业务，四级仅内部整改不外推。因此**框架必须一次性把四级模型建全**（等级选择、公开矩阵、锁定逻辑都覆盖一/二级），只是**达标校验（能力门禁）**先只放行三/四级。

## 5. 核心设计路径（架构骨架）

```
                       ┌───────────────────────────────────────────┐
  检测前：等级选定  →   │  报告透明度等级配置（本次报告 level 1~4）    │
                       └───────────────────────────────────────────┘
                                        │
   现有各模块（人/机/料/法/环/流程/影像/数据流转）
        │  各自暴露「维度采集适配器 Adapter」
        ▼
 ┌──────────────────────────────────────────┐        ┌────────────────────┐
 │  八维度信息聚合器 (Aggregator)             │  →     │ 数据存证/防篡改接口  │
 │  归集本次报告的八维度快照 snapshot         │        │ hash / 时间戳 / 链   │
 └──────────────────────────────────────────┘        └────────────────────┘
        │                                                     │
        ▼                                                     ▼
 报告签发 → 生成唯一报告码 report_code → 写入映射表 + 快照冻结（不可篡改）
        │
        ▼
 报告首页印刷溯源二维码（复用短链基建：QR → /l/{code} → 302）
        │
        ▼
 ┌──────────────────────────────────────────┐
 │  分级公开引擎 (Grading Engine)             │
 │  按 level × 八维度「公开矩阵」过滤字段     │
 └──────────────────────────────────────────┘
        │
        ▼
 报告溯源公开页 report-verify.html（委托方 / 监管扫码核验全要素）
```

**五个骨架构件（一次搭好、后续不动）**
1. **等级配置**：检测前为本次报告选定 level（1~4），受「能力门禁」约束（当前仅放行 3/4）。
2. **维度采集适配器接口**：每维度一个统一契约 `collect(reportCtx) → DimensionSnapshot`；缺失能力返回 `status: 'not_collected'`。
3. **八维度聚合器**：调用各适配器，产出 `report_transparency_snapshot`（本次报告的全量维度数据 + 采集状态）。
4. **分级公开引擎**：以「等级 × 维度公开矩阵」（§7）过滤快照，只吐出该等级应公开字段。
5. **报告码 + 公开页 + 存证**：签发时生成唯一码、冻结快照、（预留）写存证；扫码走公开 H5。

**关键点**：聚合器与公开引擎都**面向「维度契约」而非具体模块**。新增/补强某维度模块时，只实现/升级该维度适配器，骨架与公开页零改动——这正是「后续慢慢加模块」的技术保障。

### 5.1 组态物联节点采集机制（温湿度 / 视频，通用范式）

> 术语说明：数采/上位机中的「安全管家配置 / 节点设置」即本方案的**组态物联终端节点配置**。采集任务**按试验项下发**（对应附件「绑定试验检验点、字段」）。

**节点绑定与选择（参考温湿度，视频同理）**
- 在数采系统的组态物联配置页，为**检测设备**绑定节点类型（温湿度 / 视觉 / 水浸…）。
- **上位机「节点设置」**（据图 1）：展示本试验设备关联的节点类型，按组态物联终端绑定的节点列表**回显**，支持**修改绑定**；每类可选具体节点（如温湿度 01–04、视觉 01–02）或选「**不使用节点**」= 手动输入/其他数据源/跳过；未绑定的节点类型（如水浸）默认「手动/跳过」。

**节点状态模型（据图 2，用于采集前校验与公开页展示）**
- **离线**：将「无信号」与「无电量」统一归为「离线」；**主设备离线 → 其所有关联节点均离线**。
- 在线态：低电量（红）> 工作中（蓝）> 待机（绿）；网关节点列表排序：离线 > 红 > 蓝 > 绿。
- **占用**：节点若正在组态物联终端的其他场景中运行，视为「被占用」，本试验不可用。

**视频采集前置条件（试验开始前必须满足）**：视频节点已放置到指定位置、**非离线**、**未被占用**（不在其他场景运行）——满足后方可在上位机开始试验。

**时间锚定与视频回源（关键设计）**
1. 上位机点击「开始」→ **开始时间**上报数采记录；
2. 上位机数据全部上传完 → 数采记录**结束（上传完成）时间**；
3. 数采将 **开始/结束时间**回传 **LIMS 记录**（挂在该试验项/报告上）。
4. LIMS 展示时：**检测数据从数采获取**；**视频数据不落 LIMS**，而是**凭「开始/结束时间」向组态物联终端后台按时间区间请求视频**再展示（公开页按需回源）。

**对适配器契约的影响**：`image` / `env` 维度的视频/曲线**存"引用+时间锚"而非原始文件**——快照冻结的是节点标识、开始/结束时间、（可选）校验哈希；公开页展示时凭时间锚回源拉流。既省存储，又保证"扫码即可回看该试验时段"。存储期限（标准 §7.4）由组态物联终端后台按等级保障（一级视频≥3 年等）。

**无节点兜底**：任一维度选「不使用节点/手动」，该维度 `source='manual'`，公开页如实标注"人工录入/其他数据源"，并计入等级门禁（影响可达等级）。

### 12.1 分析建议：实验室固定等级授权 + 报告作废联动

**A. 实验室固定透明等级授权（标准 §8.1「报告前选定」+ §8.2「常态化授权」并存）**

- 建议新增全局参数 **`lab.transparency.authorizedLevel`（实验室授权透明等级）**，含义 = 实验室对外宣称、经评定的固定透明与数据防篡改能力等级。
- 关系：**单报告可选等级 ≤ min(能力门禁允许, 实验室授权等级)**。
  - 可出具**低于**授权等级的报告（如授权三级、某客户只需四级）——这是「选低」，不违反 §8.1「严禁降级出具」（后者指选定后执行中不得偷偷降级，与「选更低等级」是两回事）。
  - **不可**出具高于授权/能力的报告 → 名不副实，损公信力。
- 建议当前 `authorizedLevel = 三级`（四级可出、三级补照片即达；一/二级预留）。升级须重新评定（§8.4），评定通过后调高该参数。
- UI：报告编制的等级选择器默认取 `authorizedLevel`；高于它的等级走「可选走预留」（登记升级诉求，不放行）。**一句话：把"实验室透明水平"与"单报告等级"用这一个上限参数统一起来，正好落地标准"报告等级=实验室能力等级"的对应原则。**

**B. 报告码作废/召回联动（与合格证短链不同）**

- 合格证短链是"有效期核验"，故「流程回退即自动作废」。**报告溯源码不同**：标准 §7.5 要求报告出具后「自动归档、**永久可查**」。因此：
- 报告码状态设三态：`valid`（有效）/ `revoked`（作废召回）/ `superseded`（被新版替代）。
- 触发规则（**显式业务动作**，非流程回退自动触发）：
  - 报告**签发前**流程回退：此时**尚未生成码**，无需处理。
  - 报告正式**作废/召回**：置 `revoked`，扫码**仍可打开**（永久可查），但页面顶部醒目标注「本报告已作废/召回」及原因、时间。
  - 报告**更正换版重发**：旧码置 `superseded` 且 `supersededBy` 指向新报告码；新报告生成新码；扫旧码提示「已被 X 版替代」并可跳新版。
- 与合格证的差异点单列说明：**报告码不因流程回退自动 revoke，只随"作废/召回/换版"业务动作变更状态，且永远可扫（透明优先）**，契合监管溯源诉求。

## 13. 风险与注意

- **能力与承诺一致性**：等级即能力承诺，若门禁放宽导致「名不副实」，反而损公信力。门禁（能力校验）必须与等级严格绑定，禁止降级出具（标准 §8.1）。
- **公网暴露面**：报告全要素公开涉及数据安全，公开页只读、仅吐分级字段，需与内网主数据隔离（参考短链方案 2 边缘只读）。
- **存储期限合规**：影像/日志按标准 §7.4 分级留存，需在参数与归档策略中落地。
- **诚实降级**：缺失维度一律显式「暂未采集」，不得用占位数据充数，避免造假风险。
