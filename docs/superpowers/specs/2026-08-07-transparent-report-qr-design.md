## 0. 一句话结论

先搭「**报告级溯源二维码 + 八维度信息聚合器 + 分级公开引擎**」这套骨架，用现有数据即可**真实出具三级（可追溯）/ 四级（可公示）**报告；**一级 / 二级**先建模、页面预留占位，随后按「过程影像、环境监测、设备自动采集、人员资质、数据存证」等**可插拔模块**逐个接入后**解锁**。这与老板「框架先搭、能力不足处后续补模块」的思路完全一致。

## 1. 背景与目标

### 1.1 标准核心逻辑（来自 Q/YM 006—2026）

- **一报告一码**：报告首页印刷唯一溯源二维码，与本次检测终身绑定、不可复用、不可篡改；扫码查看**对应等级下**的公开内容。
- **报告等级 = 实验室能力等级**：出具何种等级的透明报告，即代表实验室对应的透明运行与数据防篡改能力。
- **双核心评级**：以「①二维码信息公开完整度 + ②数据流转自动化程度」为双核心，由高到低分四级。
- **八大维度**：人、机、料、法、环、试验流程、过程影像、**数据流转**（新增核心维度：人员干预越少、自动流转越高、篡改概率越低，等级越高）。
- **等级前置选定**：实验室在检测前按客户需求选定本次报告等级，选定后必须严格执行对应等级要求，严禁降级出具。

### 1.2 本项目目标

1. 在报告链路中集成「报告级」唯一溯源二维码，扫码进入**分级公开页**，展示本次检测的八维度信息。
2. 建立四级透明度等级模型与「等级 ↔ 公开内容」的严格锁定（后台按等级控制展示）。
3. 搭建**八维度信息聚合器**：从现有各模块自动归集数据，缺失维度显式标注「暂未采集/该等级不公开」。
4. **框架优先**：先支撑现实可达的三/四级完整闭环；一/二级预留，能力模块逐步补齐后解锁。

### 1.3 老板意图（框架先搭）

> 「框架先搭出来，系统基础能力不行的地方后续再慢慢增加模块功能，比如人员资质管理等这些我们目前都没有。」

设计原则据此定为：**骨架稳定 + 维度可插拔 + 等级按能力解锁**。骨架（二维码、聚合器、公开页、等级引擎、存证接口）一次搭好且不随维度增减变动；每个维度是一个**采集适配器（Adapter）**，缺失时降级为占位，补齐后即插即用，不改骨架。

## 2. 与现有「合格证短链」的关系（重要边界）

系统已有一条**样品级**溯源线：合格证短链（`short-link-qr.js` + `cert-verify.html`），用于「某个样品是否合格、是否在有效期内」。本方案是**另一条平行的报告级**溯源线，二者**不可混用**：

| 维度 | 现有：合格证短链 | 本方案：报告溯源二维码 |
|------|------------------|------------------------|
| 绑定对象 | 单个**样品**（sample_no） | 整份**报告**（report_no / 本次检测全要素） |
| 载体位置 | 合格证 / 样品标签 | **报告首页显著位置** |
| 扫码内容 | 合格与否、再检日期 | 八维度信息，**按透明度等级分级公开** |
| 核心诉求 | 防伪、有效期核验 | 透明度分级 + 数据防篡改能力展示 |
| 状态规则 | valid/expired/revoked（签发后发码、回退作废） | 报告签发后生成、终身绑定、不可复用；报告作废/召回联动 |

**复用策略**：短链跳转基建（`/l/{code}` → 302 → 公开 H5、内网/公网 Base 切换、本地 QR 生成、局域网/公网三种部署方案）可**直接复用**，无需重建；仅新增「报告级」的 code 命名空间、映射表与公开页。建议报告码前缀区分（如 `R` 段），避免与合格证码混淆。

## 3. 现有能力盘点 × 八维度差距分析

> 结论：三/四级所需信息**现网基本齐备**；一/二级所需的**实时影像、环境监测、设备自动采集、人员资质、强制防篡改**属于当前缺失能力。

| 维度 | 标准高阶要求 | 现网已具备 | 现网缺口（→ 后续模块） | 三/四级可达 |
|------|--------------|------------|------------------------|:-----------:|
| **人** | 姓名、资质证书、操作授权、培训考核；不接触原始数据 | 检测员选择（`inspector-select.js`）、角色管理（`testos-role-mgmt`）、当前用户 | **人员资质管理**（证书/授权/培训考核） | ✅（仅姓名/编号） |
| **机** | 编号、校准证书、维护记录、**实时运行参数曲线**、自动采集 | 设备管理：编号、校准状态、下次校准、证书编号、校准机构、校准报告、维护事件历史（`equip-mgmt.html`） | 设备**实时参数曲线**、**自动采集**（→ IoT/DCS 采集模块） | ✅（编号+校准证书） |
| **料** | 来源、编号、全流程自动流转、耗材合格证明/批次 | 样品管理全流程（收样/制备/发样/还样/退样）编号、流转、时间、责任人 | **耗材管理**（合格证明/批次自动记录） | ✅（样品编号+关键流转节点） |
| **法** | 执行标准全文、作业指导书、算法固化自动计算、人工不可改逻辑 | 标准管理（`standard-mgmt.html`）、判定规则、报告判定 | **作业指导书**（占位）、计算逻辑固化程度 | ✅（标准编号+原始数据摘要） |
| **环** | 全过程温湿度实时曲线、环境布局、安全环保、自动上传 | 无 | **环境监测**（温湿度 IoT 采集/曲线） | ⚠️ 三级需「平均温湿度」，四级不公开——三级需最小补采集或人工录入 |
| **试验流程** | 委托—收样—制样—检测—复核—报告全节点时间/责任人自动留痕 | 全流程节点建模（`flow-stages.js`）、各环节时间/责任人 | 节点留痕的**自动化与完整度** | ✅（核心节点） |
| **过程影像** | 关键节点照片 / 关键环节视频 / 全程连续视频 / 实时监控 | 无 | **过程影像模块**（照片上传→视频→监控回看） | ⚠️ 三级需 2–5 张关键照片——需轻量照片上传；四级无需 |
| **数据流转** | 采集→传输→存储→计算→复核→生成全自动、人员不可篡改、全程留痕 | 试验检测**以人工录入为主**（`test-detect-edit.html`）、数据审核（`data-audit.html`）、操作日志 | **自动采集/计算闭环**、**强制防篡改存证**（哈希/链）、修改留痕强化 | ✅（三级=人工录入+修改留痕；四级=简单存储） |

**能力小结**
- 现在就能达标的维度：人（姓名/编号）、机（校准证书）、料（样品流转）、法（标准编号）、试验流程（核心节点）、数据流转（三/四级人工形态）。
- 需最小补齐才能达三级的：**环（平均温湿度）**、**过程影像（关键照片）** —— 三级要求这两项，四级不要求。
- 需要专门模块方可迈向二/一级的：过程影像（视频/监控）、环境实时曲线、设备自动采集、人员资质、耗材、数据自动闭环 + 强制防篡改。

## 4. 四级等级可达性评估

| 等级 | 名称 | 二维码公开总要求 | 依赖能力 | 当前可达性 |
|:----:|------|------------------|----------|-----------|
| 四级 | 可公示 | 最低合规信息，无影像 | 现网数据即可 | ✅ **现在可出具** |
| 三级 | 可追溯 | 八维度核心信息 + 2–5 张关键照片，无视频；有修改留痕 | 需**关键照片上传** + **平均温湿度**（可人工录入）+ 修改留痕 | ✅ **补两项最小采集后可出具** |
| 二级 | 可视化 | 八维度完整 + 关键节点视频；高自动化，仅少量人工复核 | 需视频采集、设备自动采集、数据自动流转 | ⛔ 预留，待模块接入解锁 |
| 一级 | 全要素 | 100% 完整 + 全程连续视频 + 实时监控；全自动闭环，人员不可篡改 | 需无人化试验、全链路自动、强制防篡改存证 | ⛔ 预留，待模块接入解锁 |

**产品策略（对应标准 §9）**：一/二级为核心竞争力（国央企/电网/招投标），三级面向普通市场化业务，四级仅内部整改不外推。因此**框架必须一次性把四级模型建全**（等级选择、公开矩阵、锁定逻辑都覆盖一/二级），只是**达标校验（能力门禁）**先只放行三/四级。

## 5. 核心设计路径（架构骨架）

```
                       ┌───────────────────────────────────────────┐
  检测前：等级选定  →   │  报告透明度等级配置（本次报告 level 1~4）    │
                       └───────────────────────────────────────────┘
                                        │
   现有各模块（人/机/料/法/环/流程/影像/数据流转）
        │  各自暴露「维度采集适配器 Adapter」
        ▼
 ┌──────────────────────────────────────────┐        ┌────────────────────┐
 │  八维度信息聚合器 (Aggregator)             │  →     │ 数据存证/防篡改接口  │
 │  归集本次报告的八维度快照 snapshot         │        │ hash / 时间戳 / 链   │
 └──────────────────────────────────────────┘        └────────────────────┘
        │                                                     │
        ▼                                                     ▼
 报告签发 → 生成唯一报告码 report_code → 写入映射表 + 快照冻结（不可篡改）
        │
        ▼
 报告首页印刷溯源二维码（复用短链基建：QR → /l/{code} → 302）
        │
        ▼
 ┌──────────────────────────────────────────┐
 │  分级公开引擎 (Grading Engine)             │
 │  按 level × 八维度「公开矩阵」过滤字段     │
 └──────────────────────────────────────────┘
        │
        ▼
 报告溯源公开页 report-verify.html（委托方 / 监管扫码核验全要素）
```

**五个骨架构件（一次搭好、后续不动）**
1. **等级配置**：检测前为本次报告选定 level（1~4），受「能力门禁」约束（当前仅放行 3/4）。
2. **维度采集适配器接口**：每维度一个统一契约 `collect(reportCtx) → DimensionSnapshot`；缺失能力返回 `status: 'not_collected'`。
3. **八维度聚合器**：调用各适配器，产出 `report_transparency_snapshot`（本次报告的全量维度数据 + 采集状态）。
4. **分级公开引擎**：以「等级 × 维度公开矩阵」（§7）过滤快照，只吐出该等级应公开字段。
5. **报告码 + 公开页 + 存证**：签发时生成唯一码、冻结快照、（预留）写存证；扫码走公开 H5。

**关键点**：聚合器与公开引擎都**面向「维度契约」而非具体模块**。新增/补强某维度模块时，只实现/升级该维度适配器，骨架与公开页零改动——这正是「后续慢慢加模块」的技术保障。

## 6. 数据模型（原型 mock 形态，供后端映射）

```javascript
// 6.1 本次报告的透明度配置（检测前选定）
ReportTransparencyConfig = {
  reportNo,                 // 报告编号
  entrustNo,                // 委托编号
  level,                    // 1 | 2 | 3 | 4
  levelName,                // 全要素 / 可视化 / 可追溯 / 可公示
  selectedBy, selectedAt,   // 选定人/时间
  capabilityCheck: {        // 能力门禁结果（达标校验）
    passed: boolean,
    missing: ['process_image', 'env'] // 未满足该等级的维度
  }
}

// 6.2 八维度快照（签发时冻结）
ReportTransparencySnapshot = {
  reportNo, level, frozenAt,
  dimensions: {
    person:   { status, items: [{ name, certNo?, authorization?, training? }] },
    equipment:{ status, items: [{ code, calibCertNo, nextCalib, calibOrg, curve? }] },
    material: { status, items: [{ sampleNo, source, flow: [...], consumable? }] },
    method:   { status, standards: [{ code, name, fullTextUrl? }], sop?, calcLocked? },
    env:      { status, avgTempHumidity?, curveUrl?, layout? },
    flow:     { status, nodes: [{ node, time, owner }] },
    image:    { status, photos: [url], videos?: [url], liveMonitorUrl? },
    dataflow: { status, mode, autoLevel, editable, changeLog: [...] }
  },
  // status ∈ 'ok' | 'partial' | 'not_collected' | 'not_public_at_level'
  attestation: { hash?, timestamp?, chainTxId? }  // 防篡改存证（预留）
}

// 6.3 报告码映射（复用短链基建，独立命名空间）
ReportCodeRegistry[code] = {
  reportNo, level,
  status: 'valid' | 'revoked',   // 报告作废/召回联动
  publicUrl,                     // 302 目标：report-verify.html?code=
  createdAt
}
```

`status` 枚举让公开页对每个维度都有明确表达：`ok`=正常公开、`partial`=部分采集、`not_collected`=暂未采集（诚实告知，不伪造）、`not_public_at_level`=该等级不公开（如四级的「环」）。

## 7. 分级公开矩阵（等级 × 维度 → 系统字段来源）

> 依据标准 §6，落到系统可取字段。「—」= 该等级不公开；`(需模块)` = 依赖尚未建设的能力模块。

| 维度 | 四级·可公示 | 三级·可追溯 | 二级·可视化 | 一级·全要素 |
|------|-------------|-------------|-------------|-------------|
| 人 | 操作人员姓名 | 姓名、资质编号 `(资质模块)` | 姓名、有效资质、操作授权 `(资质模块)` | 姓名、资质证书、授权、培训考核 `(资质模块)` |
| 机 | 编号+「合格」 | 编号、最近有效校准证书 ✅ | 编号、校准、维护、关键运行数据 `(采集)` | 编号、校准、维护、**实时参数曲线** `(采集)` |
| 料 | 样品编号 ✅ | 样品编号、关键流转节点 ✅ | 样品编号、流转、耗材合格证明 `(耗材)` | 来源、编号、全流程自动流转、耗材批次 `(耗材)` |
| 法 | 执行标准名称 ✅ | 标准编号、原始数据摘要 ✅ | 标准编号、作业流程、记录摘要 | 标准全文、作业指导书、算法固化 `(SOP)` |
| 环 | — | 平均温湿度 `(需采集/录入)` | 温湿度汇总 `(环境模块)` | 全过程温湿度曲线、布局、安全环保 `(环境模块)` |
| 试验流程 | 起止时间 ✅ | 收样/试验/报告三节点 ✅ | 全流程节点+时间+责任人 ✅ | 全流程节点自动留痕 ✅ |
| 过程影像 | — | 2–5 张关键照片 `(照片上传)` | 关键节点视频片段 `(视频)` | 全程连续视频+实时监控回看 `(监控)` |
| 数据流转 | 人工录入、简单存储 ✅ | 半自动、人工录入、**修改留痕** ✅ | 大部分自动、仅复核人工、原始不可改 `(采集+存证)` | 全链路无人化、人员不可篡改 `(采集+存证)` |

✅ = 现网数据可直接支撑；这也再次印证 **三/四级可先落地**。

## 8. 信息架构 / 菜单落地

复用现有 iframe 菜单骨架（`index.html`），最小新增：

| 位置 | 新增/改动 | 说明 |
|------|-----------|------|
| **报告管理** | 「报告编制」内新增**透明度等级选择**；「报告签发」触发**生成报告码+冻结快照** | 等级前置选定 + 签发生成码 |
| **报告管理** | 新增页 `report-verify.html`（报告溯源公开页，独立 H5，等同 `cert-verify.html` 的报告版） | 扫码落地页，分级展示 |
| **报告管理/检测管理** | 新增「透明报告」管理视图（可选）：报告码列表、等级、快照、作废/召回 | 运营/抽查（对应标准 §8.3 定期抽查） |

## 13. 风险与注意

- **能力与承诺一致性**：等级即能力承诺，若门禁放宽导致「名不副实」，反而损公信力。门禁（能力校验）必须与等级严格绑定，禁止降级出具（标准 §8.1）。
- **公网暴露面**：报告全要素公开涉及数据安全，公开页只读、仅吐分级字段，需与内网主数据隔离（参考短链方案 2 边缘只读）。
- **存储期限合规**：影像/日志按标准 §7.4 分级留存，需在参数与归档策略中落地。
- **诚实降级**：缺失维度一律显式「暂未采集」，不得用占位数据充数，避免造假风险。

## 附录 A. 标准四级 × 八维度公开要求（原文摘要）

见 `Q/YM 006—2026` §6.1–6.4。要点：一级=八维度 100% + 全程连续视频 + 实时监控 + 全自动闭环、人员不可篡改；二级=八维度完整 + 关键节点视频 + 高自动化、少量人工复核；三级=八维度核心信息 + 2–5 张关键照片、无视频、修改留痕；四级=最低合规信息、无任何影像、人工录入为主、无强制防篡改。
