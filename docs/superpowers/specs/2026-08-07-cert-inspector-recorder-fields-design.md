# 合格证人员字段：检测员 / 记录员 / 合并位（定稿）

**日期**: 2026-08-07  
**范围**: 合格证模版字段池、编辑器互斥与展示方式同步、打印选人与证面渲染  
**状态**: 定稿（待实现）  
**关联**:
- 母设计：`2026-07-31-label-cert-configurable-design.md`
- 配置原型：`template-config.html?type=labelCert` / `js/label-cert-*.js`
- 打印入口：`label-print.html` / `cert-qualified-print.html` / `cert-print-*.html`
- 参数：`param-config.html`（`cert.inspector.max` / 新增 `cert.recorder.max`）

---

## 1. 背景与目标

### 1.1 背景

现网合格证仅提供单一人员字段 `inspectors`（显示名「检查员」），打印时只选检验人员。实际很多单位证面需要**检测员 + 记录员**双角色，部分版式还将两角色合在同一位置展示。

### 1.2 目标

1. 合格证元件库业务字段提供三个人员元素：**检测员**、**记录员**、**检测员/记录员**。
2. 编辑器落实互斥：有合并位则不可再放单项；无合并位时两单项可并存。
3. 同一模版内人员字段**共用一种展示方式**（姓名文本 / 电子签名）；在任一人员字段内容面板修改后同步到全部人员字段。
4. 打印选人列由模版实际配置的人员字段决定；人数上限参数化。
5. 兼容既有 `inspectors` 模版与打印载荷，不强制数据迁移。

### 1.3 非目标

- 样品标签增加人员字段
- 核校人员等第三角色
- 改变合格证门禁、短链协议、纸张/自由设计主路径
- 人员与资质系统的强绑定（仍用现有可选人员列表 Mock）

---

## 2. 方案选型

采用**三个独立 `fieldId` + 字段池/互斥层规则**（方案 1），不引入「人员元件 + roleMode」新元件类型。

---

## 3. 数据模型与字段池

### 3.1 合格证业务字段池（人员相关）

| fieldId | 默认显示名 | 打印数据 | 说明 |
|---------|-----------|----------|------|
| `inspectors` | 检测员 | `data.inspectors[]` | 兼容旧模版；原显示名「检查员」改为「检测员」 |
| `recorders` | 记录员 | `data.recorders[]` | 新增 |
| `inspectorsRecorders` | 检测员/记录员 | 同时读上述两数组 | 合并位；不单独存第三数组 |

其余合格证字段（试样名称、规格型号、日期、送检单位等）不变。样品标签字段池不含人员字段。

### 3.2 运行参数

| 参数键 | 名称 | 默认 | 说明 |
|--------|------|------|------|
| `cert.inspector.max` | 合格证检测员上限 | `2` | 已有；文案由「检验人员」调整为「检测员」 |
| `cert.recorder.max` | 合格证记录员上限 | `1` | 新增 |

### 3.3 兼容

- 历史模版元素 `fieldId === 'inspectors'` 继续有效；加载后按检测员处理。
- 字段池列表项默认 label 改为「检测员」；用户已改过的 `label` 属性以元素自身为准，不覆盖。
- 旧打印 URL 仅带 `inspectors` 时仍可渲染；缺 `recorders` 时按空数组处理（若模版需要记录员则打印前校验拦住）。

## 4. 编辑器行为

### 4.1 元件库互斥

人员字段在合格证内容层业务字段区展示。已占用规则：

| 模版已占用 | 元件库禁用 |
|------------|------------|
| `inspectorsRecorders` | `inspectors`、`recorders` |
| `inspectors` 和/或 `recorders` | `inspectorsRecorders` |
| 无人员字段 | 三个均可添加 |

补充约束：

- 「检测员」与「记录员」可同时存在。
- 同一 `fieldId` 仍最多 1 个（沿用现有字段池占用规则）。

### 4.2 展示方式（模版内全局统一）

- 人员字段判定：`fieldId ∈ {inspectors, recorders, inspectorsRecorders}`。
- 内容面板保留「展示方式：姓名文本 / 电子签名」（属性名继续用 `inspectorDisplay`：`text` | `esign`）。
- 在**任一**人员字段上修改展示方式时，写回模版内**所有**人员字段的 `inspectorDisplay`。
- 选电子签名时：该字段（及同步后的其他人员字段）下划线固定为「无」（沿用现逻辑）。

### 4.3 预览演示数据

编辑器底层 demo 数据建议：

```javascript
inspectors: ['张三', '李四'],
recorders: ['王五']
```

便于同时预览单项与合并位。

### 4.4 合并位文本 / 电子签拼接（预览与打印共用）

**姓名文本**

1. 检测员多人用 `、` 连接；记录员同理。
2. 两段之间用 ` 、`（顿号前有空格）连接。
3. 例：检测员张三、李四 + 记录员王五 → `张三、李四 、王五`。
4. 若一侧为空：只输出非空一侧（打印门禁通常不允许空，预览/容错仍需定义）。

**电子签名**

- 按顺序依次放入签名占位/图片：**先全部检测员，再全部记录员**。
- **不加**顿号或其它文本分隔符。

## 5. 打印选人与渲染

### 5.1 由模版推导所需角色

解析目标合格证模版 `elements`：

| 模版含有的 fieldId | 打印需要选择 |
|--------------------|--------------|
| `inspectors` | 检测员 |
| `recorders` | 记录员 |
| `inspectorsRecorders` | 检测员 + 记录员 |
| 均无 | 不弹人员选择，直接进入打印 |

### 5.2 弹窗与批打列表

- 仅展示模版需要的角色列（检测员 / 记录员 / 两者）。
- 上限：检测员 `cert.inspector.max`；记录员 `cert.recorder.max`。
- 校验：模版需要的角色至少各选 1 人；超上限拦截。
- 记忆：检测员、记录员分 key 存 localStorage；首次必选；后续若记忆仍满足当前模版需求可沿用（对齐现「首次必选、之后记忆」）。
- 载荷：URL / 打印数据增加 `recorders`（逗号分隔）；`inspectors` 保持不变。
- 批打页行内改人：只露出模版需要的角色列。

### 5.3 渲染

| fieldId | 行为 |
|---------|------|
| `inspectors` | 按展示方式输出检测员姓名或电子签 |
| `recorders` | 按展示方式输出记录员姓名或电子签 |
| `inspectorsRecorders` | §4.4 规则，顺序「先检测员后记录员」 |

### 5.4 门禁（不变）

报告签发及后续 **且** 判定合格；不合格禁止打印合格证。

## 7. 验收要点

1. 合格证字段池可见「检测员」「记录员」「检测员/记录员」三项；样品标签无此项。
2. 放入合并位后，两单项在元件库禁用；删除合并位后单项可再加；两单项并存时合并位禁用。
3. 任一人员字段切换「电子签名」后，模版内其他人员字段同步为电子签名，且下划线为「无」。
4. 合并位文本预览形如 `张三、李四 、王五`；电子签为三枚签名依次排列、无顿号。
5. 仅配置检测员的模版：打印只选检测员；仅记录员同理；合并位或两单项：两列都要选。
6. 检测员最多 2（可改参数）、记录员最多 1（可改参数）；超限与未选拦截正确。
7. 旧模版仅含 `inspectors` 时行为与改前一致（显示名默认「检测员」）。
8. 合格证门禁与短链逻辑不受影响。

## 8. 决议记录

| 议题 | 决议 |
|------|------|
| 实现方案 | 三独立 fieldId + 互斥层 |
| 打印列 | 取决于模版是否配置对应人员字段 |
| 合并位含义 | 同一位置按序放入检测员与记录员的姓名或电子签 |
| 合并位顺序 | 先全部检测员，再全部记录员 |
| 文本分隔 | 角色内 `、`；角色间 ` 、`；电子签无分隔符 |
| 人数上限 | `cert.inspector.max=2`；`cert.recorder.max=1` |
| 展示方式 | 模版内全局统一；入口在任一人员字段内容面板 |
| 旧 fieldId | 保留 `inspectors`，默认显示名改为检测员 |
