# 委托详情页 · 文件版本管理设计（ISO/IEC 17025 平衡方案）

**日期**: 2026-07-29（2026-07-30 决策定稿修订）  
**范围**: 委托详情页内业务文件的版本生命周期（系统回填 / PageOffice 人工编辑 / 查阅 / 回滚）  
**状态**: 已确认决策（残留澄清见 §12）  
**依据**: ISO/IEC 17025:2017（GB/T 27025-2019）§7.5 / §7.8 / §7.11 / §8.4

---

## 0. 已确认决策一览

| 议题 | 决策 |
|------|------|
| Q1 系统 vs 人工冲突 | **系统更新权威**：流程节点通过后回填对应位置 → 直接出新主版本并成为 current；用户只能在最新版上编辑 |
| Q1 系统历史可见性 | **系统更新产生的历史主版本：用户不可见、不可下载**；存储策略见 §4.1 / §12-F1 |
| Q2 签字/审核 | **可配置**：原始记录落款角色可配（检测/记录/核校等）；核校取数据审核节点人员（通常 1 人）；报告可双人审核 |
| Q3 流转单打版 | **仅实际发生内容回填的节点打主版本**；无变动不打版；同属系统更新，系统侧历史主版本不向用户留存展示 |
| Q4 预通知书 | **不是文件**：单据管理已去除；详情「查看更多」保留只读 HTML 预览，不纳入文件版本 |
| Q5 版本号 | **语义化 `V{major}.{minor}`**：系统更新升 major（V1.0→V2.0）；人工编辑升 minor（V2.0→V2.1→V2.2） |
| Q5 列表展示 | 各文件区块**只展示最新一版**，文件名**不带**版本后缀；历史靠操作列「查看历史」（权限控制）弹窗 |
| Q5 历史能力 | 历史版：**仅在线查看**，不可下载、不可编辑；仅最新版可编辑/下载/在线查看 |
| Q6 编辑方式 | **PageOffice 在线编辑** |
| Q6 会话内保存 | PageOffice **打开期间多次保存不落正式版本**；仅「编辑完成并关闭 PageOffice」落一个 MANUAL 次版本 |
| Q7 回滚 | **仅允许同主版本内的次版本回滚**（V1.2→V1.1；V2.2→V2.1；不可跨到 V1.x）；回滚=再生成一版，不删中间历史 |
| Q8 多格式 | **同一 version 挂 Word + PDF** |

## 1. 背景与目标

委托详情页集中展示一份委托下的业务文件。存在两类更新：

1. **SYSTEM**：流程节点通过后，把该节点信息回填到文件对应位置（权威）  
2. **MANUAL**：授权用户用 PageOffice 编辑并关闭保存

**目标**：

1. 操作列放开「编辑」，严格权限 + 阶段闸门  
2. 人工修订可追溯（同主版本内的次版本链 + 查看历史）  
3. 系统回填权威且用户侧不堆积系统历史版干扰  
4. 对齐 17025：技术记录/报告修改留痕、权限、防静默篡改（在「系统不向用户展示历史主版」前提下，用审计日志与当前指纹兜底，见 §5 / §12-F1）

（预通知书已从单据管理去除，与本设计一致。）

## 3. 版本号语义

### 3.1 格式

`V{major}.{minor}`，展示如 `V1.0`、`V1.1`、`V2.0`。

| 事件 | 版本变化 | source |
|------|----------|--------|
| 首次系统生成 | `V1.0` | SYSTEM |
| 系统再次回填/重生成（有内容变化） | `V{n}.0` → `V{n+1}.0` | SYSTEM |
| 基于当前主版本人工编辑并关闭 PageOffice | `V{n}.{m}` → `V{n}.{m+1}` | MANUAL |
| 同主版本内回滚（见 §7） | 再生成 `V{n}.{m+1}`，内容取自目标次版本 | MANUAL（rollback） |

**规则**：

- 系统更新**只升 major，minor 归零**（新主版永远是 `V{n}.0`）  
- 人工编辑**不升 major，只升 minor**  
- 无内容变化的流程节点**不打版**

### 3.2 用户可见范围（关键）

| 版本类型 | 用户「查看历史」 | 下载 | 编辑 | 在线查看 |
|----------|------------------|------|------|----------|
| 当前最新版（current） | 作为当前标识 | ✅（有权限） | ✅（有权限） | ✅ |
| 同主版本下的历史 **MANUAL** 次版本（如 V2.1，当 current=V2.2） | ✅ 可见 | ❌ | ❌ | ✅ 仅预览 |
| **已被取代的 SYSTEM 主版本**（如曾存在的 V1.0，当前已是 V2.0） | ❌ 不可见 | ❌ | ❌ | ❌ |
| PageOffice 会话中途保存 | 不形成版本 | — | — | — |

> 列表区文件名**永不**拼接 `V1.0` 等后缀；版本信息只在「查看历史」弹窗内展示。

### 3.3 示例时间线

```
V1.0  SYSTEM   收样后首次生成流转单          ← 用户当时可见
V1.1  MANUAL   文控 PageOffice 关闭保存
V1.2  MANUAL   再次编辑关闭
V2.0  SYSTEM   「接收试样」节点回填           ← current；V1.x 系统侧对用户不可见
V2.1  MANUAL   基于 V2.0 编辑关闭
V2.2  MANUAL   再次编辑关闭                  ← current
       回滚到 V2.1 → 生成 V2.3（内容=原 V2.1），V2.1/V2.2 仍留在同主版本历史中
```

## 4. 触发规则

### 4.1 系统更新（SYSTEM）— 权威

1. 流程节点通过 → 将本节点信息写入文件对应位置  
2. **仅当文件内容实际发生变化**时：生成 `V{n+1}.0`，设为 current  
3. 该次系统更新相对用户而言，**旧的系统主版本不可见、不可下载**  
4. 用户若曾在旧主版本上做过人工次版本，进入新主版本后，历史弹窗**只展示当前 major 下的链**（从当前 `V{n}.0` 起的次版本）；跨 major 的人工历史是否物理删除见 §12-F1  

适用例：委托确认生成委托单/任务单；流转单各回填节点；委托变更审批通过后的单据重生成；报告系统导出等。

### 4.2 人工更新（MANUAL）— PageOffice

```
操作列「编辑」
  → 鉴权：仅 current 可编
  → 打开前：保证 current 已是正式落库版本（作为回滚基线；已是则不重复建版）
  → 打开 PageOffice（会话内 Ctrl+S / 中间保存 → 不创建 DocumentVersion）
  → 用户编辑完成 →「保存并关闭」PageOffice
  → 落一个正式版本：V{n}.{m+1}，source=MANUAL，成为 current
  → 写审计日志（操作人、时间、原因若需要、contentHash）
```

**要点**：一次 PageOffice 打开→关闭会话，最多新增 **一个** 次版本；会话内多次保存合并为关闭时那一版。

### 4.3 流转单特例

- 与其它单据相同：回填即 SYSTEM 主版本升级  
- 无内容变化的节点跳过  
- 默认不鼓励人工改流转单；若开放编辑，仍走 §4.2，且随后系统回填会升 major 覆盖为权威 current

## 5. 与 17025 的映射（平衡后）

| 标准要求 | 落点 |
|----------|------|
| 7.5 修改留痕 | **人工次版本链**完整可查（同 major）；系统主版本切换以审计日志 + 触发事件记录「何时因何节点升到 Vx.0」 |
| 7.5 / 7.11 防篡改 | current 与可见历史版 contentHash；存储层对用户隐藏的系统旧主版是否物理删见 §12-F1（建议：审计库保留元数据，对象可生命周期归档） |
| 7.8 报告 | 签发后编辑策略仍受阶段闸门；双人审核见 §6.2 |
| 6.2 人员 | 编辑/查看历史/回滚分权；原始记录落款角色可配置 |
| 4.2 保密 | 预览/下载权限与委托数据权限一致；历史版禁止下载降低扩散面 |

**平衡表述**：一般实验室文控要求「过程文件以系统回填为准」，故系统旧主版不对业务用户展示；人工修订必须在同主版本内可追溯、可回滚，满足「改过要留痕」。

## 6. 权限与签字配置

### 6.1 权限码

```
doc:{docType}:view
doc:{docType}:download          # 仅 current
doc:{docType}:edit              # 仅 current + 阶段允许
doc:{docType}:history           # 「查看历史」按钮
doc:{docType}:rollback          # 同 major 次版本回滚
doc:{docType}:preview_history   # 历史版在线查看
doc:report:issue
doc:record:audit                # 原始记录数据审核（核校）
```

操作列（按权限显隐）：

```
[在线查看] [下载] [编辑] [查看历史]
```

- 无 `history`：不显示「查看历史」  
- 非 current：无下载/编辑入口（历史弹窗内亦禁用）

### 6.2 原始记录 / 报告签字与审核（可配置）

**原始记录落款角色**（体系参数可配，按实验室/大类/记录单类型）：

| 角色槽位 | 说明 | 默认 |
|----------|------|------|
| 检测人员 | 可配是否需要 | 常开 |
| 记录人员 | 可配是否需要 | 常开 |
| 核校人员 | 可配是否需要 | 可选 |

- 需要核校时：核校人 = **数据审核流程节点**的审核人；原始记录数据审核一般 **一人**  
- 不需要核校时：落款不展示/不校验核校槽  

**报告审核**：

- 支持配置为单人 / **双人审核**  
- 与报告流程节点配置对齐；双人时两人皆通过才进入下一状态  

（签字配置属流程/表单能力，与版本号正交；版本在「审核通过触发系统回填/锁定」时仍按 §4.1。）

## 7. 回滚规则

1. 入口：在「查看历史」中，对**同 major、且非 current** 的 MANUAL 次版本提供「回滚」（需 `rollback` 权限）  
2. 允许：`V2.2` → 回滚到 `V2.1` 或 `V2.0`（同一 major）  
3. 禁止：`V2.2` → `V1.x`（跨主版本）  
4. 行为：以目标版内容**再生成**新次版本 `V{n}.{m+1}`，source 标记 `MANUAL` + `rollbackFromVersionId`；**不删除**中间版本  
5. 回滚后新版成为 current，可下载/可再编辑

## 8. 数据模型

```ts
type DocType =
  | 'entrust_form'
  | 'task_sheet'
  | 'flow_sheet'
  | 'fee_notice'
  | 'report'
  | 'mail_sheet'
  | 'return_confirm'
  | 'return_apply'
  | 'original_record';
  // 注意：无 pre_notice

interface DocumentInstance {
  id: string;
  entrustId: string;
  docType: DocType;
  specimenId?: string;
  currentVersionId: string;
  major: number;              // 当前主版本号
  createdAt: string;
}

interface DocumentVersion {
  id: string;
  instanceId: string;
  major: number;
  minor: number;              // SYSTEM 主版固定 0
  label: string;              // "V2.1" 冗余展示
  source: 'SYSTEM' | 'MANUAL';
  origin: 'generate' | 'node_backfill' | 'edit_close' | 'rollback';
  userVisible: boolean;       // SYSTEM 被取代的主版 = false；当前 major 下可见链 = true
  status: 'current' | 'superseded' | 'purged';
  reason?: string;
  triggerEvent?: string;      // 节点编码
  operatorId: string;
  operatorName: string;
  createdAt: string;
  contentHash: string;
  files: { format: 'docx' | 'pdf'; url: string; name: string }[]; // 同版本多格式
  parentVersionId?: string;
  rollbackFromVersionId?: string;
  relatedChangeRecordId?: string;
  pageOfficeSessionId?: string; // 关闭落版时关联会话，中间保存不建行
}

/** 原始记录落款配置（示例） */
interface RecordSignConfig {
  scope: 'lab' | 'category' | 'recordType';
  roles: {
    key: 'tester' | 'recorder' | 'reviewer';
    required: boolean;
    label: string;
  }[];
  reviewerFromNode: 'data_audit'; // 核校取数审节点
}
```

**PageOffice 会话**：中间保存只更新会话工作副本；`edit_close` 时一次性写入 `DocumentVersion`。

**存储原则（待 §12-F1 最终确认）**：

- 用户可见版本：对象存储保留，历史不可改 hash  
- 用户不可见的旧 SYSTEM 主版：可 `purged`（删 blob 留审计事件）或冷归档仅超管/内审角色可用

## 9. UI 方案

### 9.1 详情列表行

| 列 | 行为 |
|----|------|
| 文件名 | 无版本后缀；点开 = 最新版在线查看 |
| 生成/更新时间 | current 的时间 |
| 操作 | 在线查看 · 下载 · **编辑** · **查看历史** |

不在行上展示 `V2.1` 徽标（避免与「只展示最新文件」冲突）；如需弱提示，可用 tooltip「当前 V2.1（人工）」——**默认不做，除非产品要**。

### 9.2 「查看历史」弹窗

- 仅列出 `userVisible=true` 且 `major == instance.major` 的版本（含 `V{n}.0` 与次版本）  
- 列：版本号、来源（系统/人工/回滚）、操作人、时间、原因/触发节点  
- 行操作：在线查看；current 无「回滚」；历史 MANUAL/`V{n}.0` 在权限下可回滚（仍禁止跨 major）  
- 无下载、无编辑  

### 9.3 预通知书

维持「查看更多」只读弹窗；不出现在文件列表，无编辑/历史。

## 11. 落地节奏

1. **P0**：数据模型 major/minor；列表只显示最新；「查看历史」弹窗（含权限）  
2. **P0**：PageOffice 编辑闭环（会话中不落版，关闭落次版本）  
3. **P0**：SYSTEM 回填升 major + 旧主版对用户隐藏  
4. **P1**：同 major 回滚；流转单按节点内容变化打版  
5. **P1**：原始记录落款角色配置；报告双人审核配置  
6. **P2**：历史对比；系统旧主版归档/清理任务

## 12. 残留澄清（请再确认）

上一轮 Q1–Q8 已闭合；下列边界仍影响实现，请拍板：

### F1. 系统升到 V2.0 后，旧的 V1.0 / V1.1 / V1.2 如何处理？
- **A.** 对业务用户不可见；**物理删除**文件 blob，仅留审计日志（谁在何时因何节点升到 V2.0）  
- **B.** 对业务用户不可见；**冷归档**保留，仅内审/系统管理员角色可查  
- **C.** 业务用户不可见；质量负责人等特定角色仍可在「高级历史」查看  

### F2. 「查看历史」里是否展示当前 major 的系统基线 `V{n}.0`？
- **A.** 展示（标记「系统」），可在线看、不可下载；可作为回滚目标（回滚到纯系统版）  
- **B.** 不展示 `V{n}.0`，只展示人工次版本 `V{n}.1+`（回滚不能回到纯系统版，只能回到更早人工版）  

### F3. 回滚生成的新版版本号与来源展示？
- **A.** 普通次版本 + 来源「回滚」，如 V2.2 回滚到 V2.1 → 新建 **V2.3**（内容=V2.1）  
- **B.** 同上编号，但弹窗增加「回滚自 V2.1」字段（推荐与 A 同时）  

### F4. 编辑关闭时是否强制填写「变更原因」？
- **A.** 强制（更贴 17025）  
- **B.** 可选  
- **C.** 按文件类型配置（报告/原始记录强制，其它可选）  

### F5. 报告 `issued`（已签发/已发放）后是否仍允许 PageOffice 编辑出 V{n}.{m+1}？
- **A.** 禁止，只能走「修订报告」专项流程（通常升 major 或换报告编号）  
- **B.** 允许有权限者继续小版编辑  
- **C.** 可配置  

---

确认 F1–F5 后，可在委托详情原型上改操作列与「查看历史」弹窗。
