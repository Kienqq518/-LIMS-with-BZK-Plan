## 0. 已确认决策一览

### 0.1 首轮（Q1–Q8）

| 议题 | 决策 |
|------|------|
| Q1 系统 vs 人工 | 系统回填权威 → 新主版本并 current；仅最新版可编 |
| Q2 签字/审核 | 原始记录落款角色可配；核校取数据审核人（常 1 人）；报告可双人审核 |
| Q3 流转单 | 仅内容回填节点打主版本 |
| Q4 预通知书 | 非文件；「查看更多」只读预览 |
| Q5 版本号 | `V{major}.{minor}`；列表无后缀；「查看历史」权限控制 |
| Q6 编辑 | PageOffice；会话内保存不落版，关闭落次版本 |
| Q7 回滚 | 仅同 major 次版本；再生成一版 |
| Q8 多格式 | 同一 version 挂 Word + PDF |

### 0.2 次轮（F1–F5）

| 议题 | 决策 |
|------|------|
| F1 旧主版本 | **按角色数据权限**：业务人员只看**当前最新主版本**下的全部次版本；质量负责人等高级角色可看**旧主版本历史** |
| F1 流程回退 | 流程从下一节点**回退到上一节点**也会引起**主版本变动**（同属 SYSTEM 权威更新） |
| F2 历史是否含 `V{n}.0` | **展示**；可见范围遵循 F1 |
| F3 回滚记法 | **A+B**：新建次版本（如 V2.3）+ 字段「回滚自 Vx.y」 |
| F4 变更原因 | **本期不记录** |
| F5 签发后编辑 | **系统配置项**；「谁能改这项配置」本身也要权限控制 |

### 0.3 延伸：合规版 / 实务版一键切换

| 议题 | 决策 |
|------|------|
| M1 作用域 | **A. 整套系统一套**（实验室/租户级，非按委托） |
| M2 次版本 | 合规版下**所有人**都看不见次版本；**数据库保留**文件 |
| 合规版编辑 | **不允许任何手动编辑**；流程前进/回退只产生 SYSTEM 主版本 |
| 实现策略 | 采用 **§10.4 简版**（推荐）：不合规操作一律限制；系统更新**始终基于当前最新版内容**（含次版本）生成新主版本。**不采用**「合规期间另开主版本内容分支」的复杂方案（见 §10.3 取舍） |

已登记弹性差异（细节可继续补）：

1. 报告签发后是否允许在线编辑（实务可配 / 合规强制否）  
2. 查看历史是否展示次版本（实务按 F1 / 合规全部隐藏）

## 1. 背景与目标

两类文件更新：

1. **SYSTEM**：流程节点通过（或流程回退）后回填文件对应位置（权威）→ 升 **major**  
2. **MANUAL**：PageOffice 编辑并关闭 → 升 **minor**

目标：业务可用性与 17025 检查要求可切换；版本、权限、历史可见性分层清晰。

## 3. 版本号语义

### 3.1 格式

`V{major}.{minor}`（如 `V1.0`、`V2.1`）。

| 事件 | 变化 | source |
|------|------|--------|
| 首次生成 | `V1.0` | SYSTEM |
| 节点通过且内容变化 | `V{n}.0` → `V{n+1}.0` | SYSTEM |
| **流程回退**且文件内容需按回退后状态重写 | `V{n}.0` → `V{n+1}.0` | SYSTEM（`origin=workflow_rollback`） |
| PageOffice 保存并关闭 | `V{n}.{m}` → `V{n}.{m+1}` | MANUAL |
| 文件次版本回滚（同 major） | 新建 `V{n}.{m+1}`，内容=目标版 | MANUAL + `rollbackFromVersionId` |

无内容变化 → 不打版。列表文件名**不带**版本后缀。

### 3.2 流程回退与主版本

流程存在「下一节点 → 回退上一节点」：

- 回退若导致文件对应位置内容变更（清除/改写节点回填区）→ **必须**升 major，新 `V{n+1}.0` 为 current  
- 与节点前进回填同一套 SYSTEM 规则：权威、业务默认看不到被取代的旧主版  
- 审计日志记录：`triggerEvent=WORKFLOW_ROLLBACK`、自节点、至节点、操作人  

> 主版本号表示「系统权威内容世代」，**不表示流程前进方向**；前进与回退只要改了文件，都升 major。

### 3.3 次版本回滚（文件内容回滚，非流程回退）

- 仅同 major：`V2.2` → 可回滚到 `V2.1` / `V2.0`，不可到 `V1.x`  
- 生成新次版本（例 `V2.3`），来源展示「回滚」，并写 `rollbackFromVersionId` / 文案「回滚自 V2.1」  
- 不删中间历史  

### 3.4 PageOffice

- 打开前：保证 current 已是正式版（基线）  
- 会话内多次保存 → **不**建 `DocumentVersion`  
- 保存并关闭 → 一个 MANUAL 次版本  
- **本期不要求填写变更原因（F4）**

## 4. 「查看历史」可见性（数据权限 × 运行模式）

### 4.1 实务版下的角色分层（F1 + F2）

| 角色层级（示例） | 可见历史范围 |
|------------------|--------------|
| **业务人员** | 仅 **当前最新 major**：`V{n}.0` + 全部次版本 |
| **高级角色**（质量负责人等） | 上表 + **旧主版本整链**（含旧 major 下的次版本） |
| 无 `history` 权限 | 不显示「查看历史」 |

### 4.2 合规版下的历史（覆盖 F1）

| 角色 | 可见范围 |
|------|----------|
| **所有人**（含质量负责人） | **仅系统主版本** `V*.0`；次版本一律不展示（库中仍保留） |

### 4.3 权限码

```
doc:{docType}:history              # 查看历史（实务：当前 major；合规：仅主版本）
doc:{docType}:history_advanced     # 实务版下跨 major（合规版不解锁次版本）
doc:{docType}:rollback             # 同 major 次版本回滚（合规版禁用）
doc:{docType}:edit                 # PageOffice（合规版全员禁用）
doc:report:edit_after_issue_config # 实务版配置「签发后是否可编辑」
lab:run_mode:switch                # 切换合规/实务
```

### 4.4 历史弹窗操作

| 版本 | 在线查看 | 下载 | 编辑 |
|------|----------|------|------|
| current | ✅ | ✅（有下载权） | 仅实务版 + 有编辑权 + 阶段允许 |
| 可见的历史版 | ✅ | ❌ | ❌ |

## 10. 合规版 / 实务版一键切换

### 10.1 问题

迎检要合规表现；日常要客户实务弹性。需要系统级一键切换，并控制改动量。

### 10.2 作用域与模式

| 模式 | 代号 | 定位 |
|------|------|------|
| **合规版** | `compliance` | 迎检 / 内审；强制标准底线 |
| **实务版** | `practical` | 客户实际作业；白名单弹性可配 |

- **作用域：整套系统一套（M1=A）**，不按委托/大类拆  
- 切换需 `lab:run_mode:switch`，写审计  

### 10.3 方案取舍：为什么不做「合规期主版本内容分支」

曾考虑的复杂路径：

> 切到合规后次版本不展示；之后流程「只在主版本上更新」；再切回实务时，要处理「流程前已有次版本、合规期又在主版本上走了」的分叉。

| 维度 | 复杂路径 | **简版路径（采纳）** |
|------|----------|----------------------|
| SYSTEM 回填基线 | 从裸主版本或平行分支取，易丢次版本已改内容 | **始终取 current（最新版，可含次版本）** 再生成新 `V{n+1}.0` |
| 切回实务 | 需合并 / orphan 次版本，状态机复杂 | 次版本一直在库；新主版本已含当时最新内容，谱系清晰 |
| 代码面 | 双套写路径、模式感知祖先、切换补偿 | **一层 ComplianceGuard**（禁编辑 / 滤历史 / 盖弹性配置） |
| 数据正确性 | 有丢改风险 | 流程更新内容准确 |
| 相对改动量 | **大**（框架级） | **中小**（门禁 + 查询过滤 + 配置覆盖） |

**结论：不做复杂分支。那种设计整体改动大，且切回实务难自洽。采纳你提到的简版。**

### 10.4 简版规则（定稿）

```
最终行为 = ComplianceGuard(mode, PracticalFlexibilityConfig)
SYSTEM 新主版本内容基线 = 当前 current 文件（无论 V{n}.0 还是 V{n}.{m}）
```

#### 合规版强制行为

1. **禁止全部手动编辑**（PageOffice / 次版本回滚入口均不可用）  
2. **历史弹窗只展示系统主版本** `V*.0`；次版本对**所有人**不可见；**DB 保留**  
3. 弹性配置入口全部隐藏；运行时忽略实务配置，强制合规值  
4. 流程前进/回退照常；有内容变化 → 新 `V{n+1}.0`，基线 = **当时 current 最新内容**  

#### 实务版行为

1. 按权限可编辑 → 产生次版本  
2. 历史按 F1：业务看当前 major 全链；质量负责人可看旧 major  
3. 显示弹性配置区（如「签发后允许编辑」），受单独配置权限控制  

#### 模式来回切换时的数据故事

```
实务：V2.0 → V2.1 → V2.2(current)
      ↓ 切到合规（次版本隐藏，禁止再编）
合规：流程节点回填 → 以 V2.2 内容为基线生成 V3.0(current)
      历史仅见 … V2.0、V3.0
      ↓ 切回实务
实务：历史重新可见 V2.1、V2.2；current=V3.0
      可继续基于 V3.0 编辑出 V3.1…
```

无需「合规期专用主版本线」。

### 10.5 已登记的两处弹性差异

#### （1）报告签发后是否允许在线编辑

| | 实务版 | 合规版 |
|--|--------|--------|
| 配置入口 | 显示；需 `edit_after_issue_config` | 隐藏 |
| 运行时 | 随配置 | **强制否**；仅流程退回后可再编 |

> 合规版已「禁止全部手动编辑」，本项是实务版内细闸；合规版双重锁死。

#### （2）查看历史是否展示次版本

| | 实务版 | 合规版 |
|--|--------|--------|
| 次版本 | 按 F1 角色展示 | **所有人都不展示**（DB 保留） |
| 主版本 | 按 F1 | 仅展示各 `V*.0` |

### 10.7 切换审计

记录 `fromMode`、`toMode`、`operator`、`time`、`reason`；可选快照当时弹性配置。

### 10.8 弹性注册表

```ts
interface FlexibilityFlag {
  key: 'allowReportEditAfterIssue' | string;
  title: string;
  complianceForcedValue: unknown;
  configPermission: string;
  affects: Array<'edit_gate' | 'history_ui' | string>;
}
```

已登记：`allowReportEditAfterIssue`、`historyHideManualMinorsInCompliance`。后续不合规点往表里加即可，**不必再改版本写入主路径**。

### 10.9 非目标

- 按委托/大类切换模式  
- 合规版物理删除次版本  
- 合规期「绕过 current、只从裸 V{n}.0 再生」

## 11. 落地节奏

1. **P0**：major/minor；列表最新；查看历史（实务 F1）  
2. **P0**：PageOffice 关闭落次版本；SYSTEM 以 current 为基线升 major（含流程回退）  
3. **P1**：同 major 内容回滚（A+B）  
4. **P1**：运行模式简版 Guard（禁编、滤次版本、弹性覆盖）+ 签发后编辑配置项  
5. **P2**：落款/双人审核；弹性表扩项  

> 版本主路径与模式切换**解耦**：即使暂缓做切换，P0「SYSTEM 总是基于最新 current」仍应先落地。
