# 检测任务单 · 按检测员分单生成设计

**日期**: 2026-07-31  
**范围**: 检测任务单生成时机、多检测员多文件、接收回填、委托详情列表列  
**状态**: 已确认；原型已落地

---

## 1. 问题

旧逻辑（或早期设想）在「样品发样」后生成**一张**检测任务单，接收人/日期置空；多名检测员在「试验检测」点「接收」时反复覆盖同一张单的接收人与日期。  
一个委托下常见多检测员并行检测，单文件覆盖会导致签收留痕错误。

## 2. 目标规则

| 项 | 规则 |
|----|------|
| 生成时机 | **试样分发**确认「发放」时生成（不再在委托确认 / 样品发样生成） |
| 生成粒度 | 同一委托下，试样分给几个检测员 → 几张检测任务单（**一人一单**） |
| 单据内容 | 仅包含该次（及后续合并到该检测员）分发给此人的试样 / 试验项目行 |
| 生成时落款 | 下发人 = 分发操作人；下发日期 = 分发日；**接收人、接收日期置空** |
| 接收回填 | 检测员在「试验检测」点「接收」→ 仅回填**分给他的那张**任务单：接收人电子签名 + 接收日期 |
| 与流转单 | 接收仍同时追加流转单「接收试样」行（互不替代） |

## 3. 委托详情列表

列顺序：

`序号` → `检测任务单` → **`检测员`** → `生成时间` → **`接收时间`** → `操作`

- 未接收：接收时间显示 `—`
- 文件名可不带检测员后缀；列表用「检测员」列区分（原型可用 `-检测员名` 后缀便于演示）
- 批量导出勾选「检测任务单」时打包该委托下**各检测员当前最新版**

## 4. 边界约定（实现时必须遵守）

1. **同一检测员多次分发**：同一委托下同一检测员已有任务单且尚未作废时，后续再分发给此人 → **合并进同一张**（更新内容，必要时升系统主版本）；不重复建空壳。  
2. **退回再分发**：试样从检测员退回后改派他人 → 原任务单按作废/归档策略处理（原型：原单保留历史，新检测员新建一单）；接收回填只写当前有效单。  
3. **未分发前**：委托详情 / 委托确认 / 样品发样页「检测任务单」区块为空态文案「试样分发后按检测员生成」。  
4. **版本**：每张任务单独立版本链；接收回填属系统内容变更 → 升 major（`origin=node_backfill`，节点=试验检测接收）。

## 5. 原型落点

| 页面 | 改动 |
|------|------|
| `test-distribute-edit.html` | 发放成功提示生成任务单；批注说明一人一单 |
| `test-detect.html` | 接收回填对应任务单签收 + 流转单行 |
| `entrust-detail.html` | 多行任务单表 + 检测员 / 接收时间列 + 预览弹窗 |
| `entrust-confirm-edit.html` / `sample-dispatch-edit.html` | 空态（尚未生成） |
| `template-config.html` | 任务单页脚占位：接收人 / 接收日期 |

## 6. 非目标

- 不改变流转单「一人一行接收试样」既有规则  
- 不在本单引入「接收部门」替代「接收人」（与纸质 SL/ZJ15-01 落款一致：下发人 / 接收人 + 日期）
