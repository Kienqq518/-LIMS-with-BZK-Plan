# 动效规格 V1（animation-spec.md）

> 输入：《视觉语言提取 V1.md》§5；方法：ui-designer 状态动效原则（短、有目的、不打断读数据）+ graphics 事件驱动 VFX 原则
> 全局：所有时长/缓动取自 `design-tokens.ts` 的 `motion`；`prefers-reduced-motion: reduce` 时仅保留状态色切换。

## 1. 相机动画曲线
| 场景 | 触发 | 曲线 | 参数 |
|---|---|---|---|
| 入场 | 页面加载完成 | `cubic-bezier(.25,.8,.35,1)` | 1200ms：从全景 1.25× 距离落到 S1 默认机位（轻微推进感） |
| 飞行定位 | `?focus=` 深链/点击房间 | 同上 | 900ms，先平移后 zoom（两段各 55%/45% 时长）；到位后目标脉冲一次 400ms |
| 巡航 idle | 60s 无交互 | linear 环绕 ≤2°/s + zoom 呼吸 ±2%（20s 周期） | 任何 pointerdown/wheel/keydown 立即接管并重置计时 |
| S2 巡检 | 手动「106 巡检」 | ease-in-out 关键帧链 | 入口→输送线→检测台1→2→机器人位，每站停留 3s，段间 1500ms |

## 2. 告警闪烁/脉冲
- 频率：**1.2s / ease-in-out / infinite**（OutlinePass `pulsePeriod:1.2` 与 CSS glow 同步）。
- 幅度：光晕 4px→12px、描边 alpha 1→0.55；**不做整块红白闪**（防癫痫风险，亮度变化 <20%）。
- 并发：同屏脉冲对象 ≤3，其余告警静态描边；超出进抽屉列表。
- 声音：V1 无（非目标）；预留 `intent:alarm-audio` 事件位。

## 3. 卡片/浮层动效
- 浮现：`opacity 0→1 + translateY 8px→0`，300ms `cubic-bezier(.2,.8,.2,1)`，多卡级联 60ms/张（按告警等级排序：A 最先）。
- 消失：150ms 仅 opacity（不缩放、不上浮，消失要"安静"）。
- 数值滚动：count-up 200ms，等宽数字容器防位移；sparkline 新采样 300ms tween 左移一格。
- 安灯操作反馈：按钮 pressed 缩放 0.97；成功后卡片降饱和并显示处理状态，**不由前端直接删除**（状态来自数据源）。

## 4. AGV/机器人路径动画
- 路径线：蓝色 `#2878FF` 虚线 dash-offset 流动，**2.4s/周期 linear infinite**；底色 `#BCD6FF` 静态实线 6px 垫底（参考图4的双层线）。
- 机器人本体：沿 `CatmullRomCurve3` 移动，巡航速度 0.8 m/s（three-world-m），转角自动降速（曲率>阈值时 0.4）；朝向切线对齐，yaw 平滑 200ms。
- 光晕：脚下蓝色径向渐变圆盘半径 1.2m，脉冲环 1.6s（与告警 1.2s 错开避免频闪叠加）。
- 到站：P 目标点 pop-in 300ms（scale 0.6→1 回弹 `cubic-bezier(.34,1.56,.64,1)`），随后工单卡浮现（§3 级联）。
- 数据驱动：位置来自调度系统位置流（1–5s 间隔），前端**插值不跳点**；断流>3 个周期 → 停走 + `stale` 灰化（诚实降级，路径线保留最后一段）。

## 5. 维度切换（5M1E）
- 切层：旧叠加层 150ms 淡出 → 新层 200ms 淡入 + 60ms 级联；相机不动（防晕）。
- 被过滤对象降透明度至 0.35 而非移除（保持空间锚定）。

## 6. 验收
- 任意动效在 1080p/Chrome 下综合帧时间 <16.7ms（profile 面板）；
- reduced-motion 全关循环类；
- 所有时长/缓动与 design-tokens.motion 一致，代码内不得出现魔法数字。


## 10. 机器人行进与避让规范（2026-11-06）

**运动学**：调度系统机器人只直线行走、原地掉头（决策 Q5）→ 路径一律曼哈顿折线，插值沿段进行，转向为瞬时角度切换，禁止弧线/平滑转向。

**扫掠包络**：机器人 `0.686 × 0.902 m`；原地掉头时包络取旋转后正方形 **0.902m**，加净空 **0.20m** → 判定半宽 `0.651m`。
后果：106 东侧墙（x=18.44）与三个制样工位（x≤17.41）之间 1.03m 窄缝**不可通行**；可用巷道为中央通道 x≈11.9–15.6。

**范围**：`RB-C-02` = 102 智能样品室 ∪ 106 无人化电缆试验区 ∪ 区间走廊（x 18.44–20.84 / z 9.64–15.14）；`RB-C-01` 自 2026-11-06 起不参与演示，停靠 102-05 充电位（`parked`，允许区域=102，路径退化为单点停靠位）。范围判定用**并集精确覆盖**（坐标压缩逐格），不能用单矩形包含——否则 102↔走廊门口会被误判越界。

**障碍**：场景内全部实体 AABB（73 个参与校验），含 `106-12 AGV 上料试验桌（双承载位）`、`106-13 检测上下料试验桌`、`106-01/02/03` 制样工位、`106-04~07` 检测工位、货架、台桌、座椅、结构柱；贴地零高物体（地面标线）不计。

**推导**：0.05m 栅格 A*（障碍按包络半宽+净空膨胀）→ 直角折线锚点 → `simplify` 时**保留折返点**（同向共线才可删，否则会把北向-excursion 塌成一条直线）。

**家位**：环线起点 `homeAnchor`。CAD 原始摆放把 106-08 放在 106-03 内、106-09 放在 106-06 内（视觉上就是"机器人压在设备里"），场景装载时必须先挪到 homeAnchor。

**校验（常驻）**：`auditRoutes()` 逐段 0.02m 采样（当前 3758 点）→ 违规写 `#twin-v2-route-audit` + `route-audit` 消息 + 左栏徽标。**违规 > 0 不上线**。


## 11. 浮层动效与相机补间（2026-11-06）

**下钻序列（顺序即正确性）**：`camera:begin` → `focus-scene{roomIds,manualRoom}` → `view` → `camera:drill`。
`view` 必须排在 `focus-scene` 之后：分组高亮模块在 `changed` 时会执行 `visual.setView('overall-101')`，先发的视角指令会被覆盖。

**为什么不能只改 `visual.zoom`**：`scene-group-highlight-v3-1.js` 的 `fitFrame`（挂在 `window.roomTourFrame`）每帧用房间包围盒重算 `camera.left/right/top/bottom`，完全不读 `zoom`。因此补间必须在它**之后**按比例缩放视锥；并且要用 `Object.defineProperty(window,'roomTourFrame',{get,set})` 组合，而不是启动时一次性 wrap——对方 `start()` 里的赋值会把一次性 wrap 顶掉（实测表现为下钻偶发退化成瞬移）。

**pan 是像素**：`whiteblue-spatial-engine.js` 把 `pan` 换算成世界偏移（`units=(top-bottom)/h`）。新增 `pan` 指令供宿主/桥接层设置；方向不靠猜——启动时用 `calibPan()` 实测「pan+40px 时参考点移动多少」来自标定，符号永远正确。

**参考点补偿**：切换前后各投影一次固定世界点 `REF(14,0.6,19)`，用它的屏幕位移与半高比例反推起始 `frScale/pan`，再补间回 1/0 → 画面「先在旧构图停住，再平滑推近」，不会跳。

**时长与降级**：下钻 760ms、切近 720ms，smoothstep；`prefers-reduced-motion:reduce` 或低配模式 → 直接落位（实测滚动浮层动画同时置为 `none`）。

**切近取景规则**：相机站到「房间中心→实体」连线的反方向（正对操作面），`elev=0.62`，目标画面半高 `max(2.4m, 实体最大边×1.9)`，实体放在画面 40% 宽 / 52% 高，信息卡贴其右侧并每帧重投影跟随。

**循环剧本**：`stop.t0 = 停靠开始时刻`（travel 段在 `t0-travelSec .. t0`）；行走段 `u` 从上一站推进到本站，停靠段 `u` 不变；末站之后为「返回 102」收尾段，倒计时 `max(0, …)`。按墙上时钟取模，保证刷新/多人/挂机同相位。


## 12. 循环剧本的四个运行时坑（2026-11-06，全部实机复现后修掉）

数学层面（对 seed 时间轴逐 0.1s 扫一圈 2023 个采样点）一次就通过，但**运行时**连着暴露四个只有跑起来才会现形的问题：

1. **`tick` 根本没调用剧本**：两处 `str.replace` 因缩进/锚点不匹配静默失败（4 空格 vs 6 空格），
   机器人仍在跑旧的随机 `progress += 0.03`，UI 冻在 `8/11 剩余 0s`，而 `/api/zone/106/cycle` 的 `live` 却是对的
   ——「接口对、画面错」。**教训**：改 mock 的广播链必须断言事件真的到达 UI（`UI 最长未变化 ≤3 次采样`），不能只看端点。
2. **参数化不一致**：剧本 `u` 是**弧长比例**，而场景取位用的是 `local*(点数-1)`（**点序号比例**）→ 速度忽快忽慢、停靠点偏移。
   现改为 `posAt(pts,u)` 按累计长度取位（`pts.__cum` 缓存，长度变化自动重算）。
3. **回绕判定恒 false**：`Object.assign(slot, r)` 就地改写同一个对象，之后再读 `prevTgt.progress` 已经等于新值
   → 一圈走完不触发「先跑到终点再从 0 起步」，收尾直接倒窜 ~20m（实测峰值 15.11m/s）。
   现先取 `prevProgress` 再合并。
4. **动画环静默停摆**：`posAt` 遇到退化路径（点数 <2）抛 TypeError，而 rAF 回调里抛错会让整条循环**无声死掉**
   ——机器人不动 + 相机补间同时失效，且控制台什么都没有。现：`posAt` 退化返回、循环体 try/catch 兜底并把错误写进
   `#twin-v2-loop-error`（QA 可断言），**动画环永不因单帧异常停摆**。

**最终做法**：有剧本的机器人，`u` 由**场景内墙上时钟**直接算（`uFromCycle`），不再依赖宿主 2s 推送插值
——推送节奏一抖（setInterval 漂移、主线程忙）就会出现「走完再等一下」的微停顿，实测峰值只有 0.57m/s；
改成自算后 30s 窗口内累计位移 14.62m、峰值 0.84m/s（剧本 0.75）、最长静止 8.0s（正是一次停靠作业）、超速样本 0。

**验收断言（写进 uxcheck）**：① 30s 位移 >6m 且峰值 ≤1.05m/s 且出现 ≥4 连帧静止（停靠）且无超速样本；
② UI 站序 == `/api/zone/106/cycle` 的 `live.order`；③ 无负倒计时；④ `#twin-v2-loop-error` 不存在。

机器人只从**实测门洞**出入 102/106。自检的墙体清单必须是 CAD 实测的 4 面，不是手写 2 面——
原清单里没有 102 西墙，所以折线在 102 侧穿墙时自检毫无反应，「违规 0」是空转出来的假安全感。

**路径（34 顶点，由 routeNodes 推导）**：`102 家位 → 102 取料位 → 向西穿 102 西门 z=11.59 → 沿走廊 x=19.64 北上到 z=25.40 → 向西穿 106 北门 → 106 北侧横巷 → 西绕 106-12 → 106 各工位 → 原路折返`。
穿越点取门洞**中心**而不是「能过就行」：106 东门 1.60m 宽、机器人扫掠 0.902m，两侧各剩 0.35m，取边侧就会蹭墙。
走廊实测贯通（0.651m 扫掠半宽下 x=19.0/19.6/20.2 在 z 9.8→28.0 每格都无障碍），走廊带内折线 **32.4m**、覆盖 z[11.59,25.40]——通过式通道，不是原地折返的盲端。

**屏上不画门洞记号**：原来把 `gate` 区间画成墙上一个 0.14×1.8m 的绿色面片，被指出「那不是门」——把规则可视化成一个不像门的方块，等于制造新的误读。
门洞这件事由折线自己走位证明（只在两处穿墙，且都落在实测开口内）。起点圆点保留（那是环线起点）。

**反向注入要注入到被测规则上**：旧注入让坏路径在 z=12.39 穿 106 东墙，结果先被判「越出允许范围」就 `continue` 了，墙体规则一条没测到却显示"抓到 40 处"。
现在注入一面**完全落在允许区域内**的假墙（x=16.0，门洞 z[12,13]），让路径在 z=15 穿它 → 报「穿墙未走门洞」40 处，这才证明墙体规则真的在跑。

## 14. 蓝框回退（2026-11-06）

`scene-group-highlight-v3-1.js` 的 `platform()` 会为**每个被激活的房间**生成一圈 `#098bff` 轮廓管（`depthTest:false`，很抢眼）。V2 曾为了「下钻有抬升感」发 `focus-scene{roomIds:全部房间}`，结果总览满屏蓝框，被产品负责人要求改回。

**现状**：V2 完全不发 `focus-scene`，分组抬升模块保持 `motion.active=[]`（轮廓不可见，实测 `visible 0 / 共 40 个构件`）；下钻的平滑感全部来自相机补间（§11），实测画面半高 14.2 → 8.2 连续 7 帧。
若以后要「单房间抬升」，必须只传 `roomIds:[选中房间]` 且**关掉轮廓**，不能再传全部房间。

**UI 滞后**：循环指示原先只在 2s 心跳里刷新，倒计时会滞后一拍（实测 UI 10/11 而端点 11/11）。现由宿主按秒用同一套时间轴公式自算（`cycleAt()`），与端点/场景保持同相位。


## 15. 底部元素删除与装载链守卫（2026-11-06）

机器人状态条（`#robotZone` + `renderRobots`）与底部说明条（`.watermark`）**整体删除**，不再跟随「收起底栏」。信息去向：机器人→区域面板「设备」块 + 告警流；来源与更新时间→每张表表头；只读声明→详情卡；Mock 标注→S3 抽屉；按键表→瞬时提示条 + 按钮 title。

**教训（连续两次）**：用「从 A 函数删到 B 函数」这类切片式删除会连带干掉不相关的声明——第一次删掉 `#alarmSum`（renderAlarms 写 null 抛错，四张表全显示数据延迟），第二次删掉 `stamp()`（装载链在 `devices.map(stamp('106'))` 处抛错，被 `.catch(fail)` 吞掉，表现为区域下拉为空、告警流为 0，但页面看起来"只是少了一块"）。
因此新增**常驻断言**：`fail() 未被触发（#freshTxt 为空）` + `区域下拉已填充 10 项` + `告警流行数>0`，任何装载链中断都会被立刻抓到。


## 16. 观察窗必须覆盖整圈（2026-11-06）

「实机穿门」断言最初用 60s、后来 90s 的观察窗都出现过 0 次穿越的假阴性：循环一圈现在 205.5s（门洞重算前是 202.3s），去程穿越 t≈23.0s（102 西门）/27.0s（106 东门）、回程 t≈192.5s（106 东门）/196.5s（102 西门），**去返相隔约 170s**，短窗口会整段错过。
现改为：在场景 iframe 内以 100ms 记录穿越事件（机器人 0.75m/s，跨墙本身只有约 1.2s，测试侧 500ms 轮询同样会漏），测试侧每 2s 轮询直到抓到 ≥2 次或满一圈。
**教训**：验证周期性演示时，观察窗长度必须 ≥ 一个周期，或者按剧本时间轴对齐到目标事件附近再采样。


## 17. 分区滚动：动画挂在「每一区」而不是整块列表（2026-11-06）

告警流改成 A/B/C 三分区（PRD FR-24）后，最初把 `translateY(-50%)` 的无缝滚动仍挂在**外层** `.stream-board` 上，出现两个现象级问题：

1. **区头跟着一起飘**：整块上移时分区标题（徽标 / 今日计数 / 「只看未解除·全部」）滚出容器被裁掉，看上去像"表头飘走"，滚到一半甚至点不到筛选按钮。
2. **被裁的行仍参与几何计算**：无缝滚动是把行集合复制一份接在后面（`rows + rows`），上半区里被遮罩裁掉的行 `boundingClientRect` 依然有效——测试直接 `click()` 时会命中相邻区头或复制行，产生"点 A 行弹出 B 条"的假失败。

修法与规则：

- 滚动动画下沉到 `.asec-track`（每区自己的 track），外层 `.stream-board` 只做排版、**永不位移**（实测三区 `animationName=asecUp,asecUp,asecUp`，外层 `=none`），区头因此恒定可见；`prefers-reduced-motion` 停动画、`.asec:hover` 暂停。
- `.asec-body` 高度按**行高**取值：实测单行 97–114px（标题折行时更高），`max-height` 从 132px 提到 **236px**（约 2 行 + 间距 + 底部 26px 渐隐区）。132px 时每一行都被遮罩裁半，读不出原因文本——这类"容器高度 vs 内容行高"的匹配必须实测量一次，不能靠目测。
- 空态文案 `今日无{分区标题}`，且空区**不加** `.scroll` 类（没有内容还滚动＝无意义的 transform）。
- **测试侧约定**（alarmlvl 已按此实现）：点告警行前先 `document.querySelectorAll('.asec-track').forEach(t=>t.style.animationPlayState='paused')` 冻结滚动，再取 `.asec[data-sec=X] .st-row`；被遮罩裁掉的半行只是看不见，几何上仍可点，断言"点某行弹出对应详情"时要以 `data-alarm` 比对而不是按屏幕位置猜。


## 18. 光点命中与键盘焦点（2026-11-06）

**光点为什么不能靠射线**：状态光点是 `visual.detail` 里的 0.045m 小球，而 CAD 引擎的拾取只 `intersectObjects([...modelRoots])`——射线根本不看它，所以点光点原本**什么都不发生**（用户反馈「增加点击设备展示设备信息弹窗」的真实缺口就在这儿）。
改成按**屏幕距离**命中：把每个光点的世界坐标投影到视口，取 `Math.hypot(dx,dy) ≤ 16px` 的最近一个。半径必须给到 16px——0.045m 的球在总览机位下只有约 8px，给 6px 实测点不中；命中后派发同一个 `space-device-select`，与点设备本体共用 `focusDevice()` + 信息卡，**不另写一套弹卡逻辑**（两套实现必然漂移）。
去重靠 `visual.selected === id`：引擎的 `onpointerup` 是属性赋值、先于我方 `addEventListener` 执行，所以进我方处理时 `visual.selected` 已是本次拾取结果，同一台设备不重复触发补间。

**物联节点标签下线**：`.orb-tag`（名称·类型）由桥接层每 800ms 轮询节点标记后追加，16 条互相压字；节点标记本身是 `<button>` 且带 `title`，点击已能出 NodeLayer 详情卡（读数/状态/更新时间/离线态），标签属于纯噪声 → 连 `showPop/closePop` 死代码一起删。`.node-reading`（实时读数胶囊）**保留**：它是数据不是身份标签，与区域视图「环境数据」同源。

**键盘焦点即暂停**：分区滚动是 CSS 动画，鼠标悬停能暂停但键盘用户没有 hover。行了 `tabindex` 之后用 `.asec:focus-within .asec-track.scroll{animation-play-state:paused}` 补齐——Tab 进某一行，那一区就停住，逐条读得完；`Enter/Space` 由 document 级代理到 `el.click()`，与鼠标同一入口。


## 19. 停靠机器人与「节拍超时」口径（2026-11-06）

演示只跑一台：`RB-C-02` 循环，`RB-C-01` 停在 102-05 充电位（实测占地 x 26.04–26.84 / z 13.07–13.88 → 停靠点取中心 26.44,13.48；与 RB-C-02 家位 (25.59,12.39) 相距 1.38m，大于两台半径和 0.90m，不会叠）。

三条实现约束：

1. **单点路径 = 不画线也不插值**：`drawRoutes` 只处理 `path.length>=2`，动画环同样早退；位置由 `homeAnchor` 落一次（`userData.homeParked`）。所以停靠不需要新代码，只需要数据诚实。
2. **停靠位也要进自检**：`auditRoutes()` 原来只扫线段（`pts.length-1` 段），单点机器人等于**完全不被校验**。现在对 `parked` 额外验一次「停靠点落在允许区域内」，违规记「停靠位越出允许区域」。注意**不查实体重叠**——停在充电桩上就是与桩重叠，那是对接不是碰撞。
3. **充电语义**：mock 里 `parked/charging` 的机器人电量**只回升**（+0.35/tick，上限 96）且 `progress=0`；在跑的才 -0.08/tick。原来所有机器人都掉电，会出现「停在桩上电量降到 12%」。

叙事口径：机器人一直在动，所以**不能写「停摆/停在巷道」**。原挂 RB-C-01 的 `AL-102` 改挂唯一在跑的 RB-C-02，两条 A 级告警都改成**节拍超时**（到站未完成握手 / 第三次到站仍未放行）；决策 Q4 的「机器人有没有卡住」由 ① 在制任务的「超时」标注（elapsedMin>plannedMin）② A 级告警 回答——两者都稳定，不随剧本相位闪一下消失。

**顺带记一类反复出现的事故形态**：`openRobot()` 与 `openDeviceByCad()` 都是「函数被切片式删掉、调用点还在」——`node --check` 通过、页面装载正常、只有点到那一行才炸（ReferenceError 只进 console，UI 看起来没坏）。
所以**每个可点入口都要有断言**：现在 pickcheck 覆盖 设备卡→查看详情、机器人卡→查看详情、未建档实体不给按钮 三条分支；smoke 覆盖告警行点击。加新按钮时同轮加断言，别等下次回归才发现"原来上个月就点了没反应"。

## 20. frScale：补间倍率必须跟着视角归位（2026-11-06）

`frScale` 是我方在引擎 `fitFrame` **之后**乘上去的视锥倍率（下钻/切近都靠它）。两个约定缺一个就会出现「画面回不去」：

1. **任何 `setView` 都要把它归位**：引擎 `setView` 只重置 `visual.zoom`，不知道 `frScale` 存在。切近设备时 `focusDevice` 把它压到 0.1~0.3，不归位的话回总览后构图仍是特写尺寸（camHH 14.2 → 10.5，实测）。
   → 桥接层包一层 `visual.setView`：`camTween=null; frScale=1; setPan(0,0)` 后再调原实现。
2. **`camera:drill` 的补间终点恒为 1**：终点原来取 `camSnap.scale`（切换前快照），语义是"从旧构图平滑过渡"，但**旧构图的缩放不该是新视角的目标缩放**——下钻时新视角的特写由引擎 fitFrame 自己算，回总览时标定机位也由它算，所以终点就该是 1。起点仍用 `s0`（快照倍率），动画观感不变。

断言在 `tests/twin/camcheck.mjs`：`hh 14.2 → 切近 4.37 → 回总览 14.2（容差 0.3）`。

**同类坑（同轮发现两处）**：停靠的机器人（单点路径）一度没有状态光点——`ensureDot` 写在动画环的路径分支里，`path.length<2` 早退就跳过它；而光点是 FR-25 里设备的唯一 3D 点击入口，于是"停着的那台点不动"。
教训：**与运动无关的事（挂光点、写状态）不能放在运动分支里**，否则任何"静止"的实体都会被静默排除。

## 22. 线路是推导出来的，不是手写的（2026-11-06）

**结构**：`seed.zone106.robots[RB-C-02].routeNodes` = 有序节点序列，每个节点要么 `kind:station`（无人化任务要到达的设备前那个定位点，带 cad/flow/taskNo/dwellSec），要么 `kind:transit`（直角拐点、门洞穿越侧、折返点）。
mock `deriveRoute()` 由此算出：`path`（逐点曼哈顿相连，长边先走再原地掉头）、`legs`（相邻定位点=业务航段 9 条）、`displayLegs`（按门洞/折返点再切 12 段，只给渲染用）、每站 `u`、`travelSec`、`t0`、`loopSec`、`pathLengthM`、`gateCrossings`。

**为什么必须推导**：上一轮改了路径没重算 `u`，11 个站会全部停错位置——而页面看起来完全正常（机器人照样跑照样停），只有对着设备坐标比对才发现。手填时间轴=定时炸弹。

**`arcOf` 的坑（本轮真实踩到）**：把定位点坐标映射回折线弧长时，若只比**垂距**，同一条直路上的多个站（106 中巷几个工位都在 x=15.49 上）垂距全是 0，取第一段 → 三个站算出同一个 u（实测 `u=0.061,0.061,0.061`）。必须用**点到线段的真实距离**（投影参数 t 夹到 [0,1] 后再算欧氏距离）。

**当前航段的画法**（参考图：浅蓝发光带 + 等距圆点）：
- 只高亮「正在走的那一段」，其余航段保持细黄线。整屏霓虹等于没有重点，也违反 PRD 反装饰红线。
- 每段几何：外发光带（1.0m 宽，opacity .10）+ 实体带（0.42m，.34）+ 中心亮线 + 等距圆点 + 下一站蓝环。
- **圆点用 InstancedMesh**：0.9m 间距、整段一个 draw call。最初用几十个独立 Mesh，一条长腿画出 168 个对象，大屏 draw call 白烧一半——改完降到 5–8 个对象。
- **腿没换不重建**：`liveState[robotId]` 存 `idx:from→to/part` 签名，变了才重画；每帧重建几何会抖。
- **长腿必须再切**：「9 站→走廊巡逻→1 站」这条业务腿约 30m，整条高亮会铺满画面，所以渲染层用 `displayLegs`。业务语义（legs=9）与视觉分段（displayLegs=12）分开，别为了好看去改业务结构。

**102 航段撤出但留痕**：`demoCycle.stops` 只留 9 个可走站点，两条 102 航程挪进 `demoCycle.unmappedStops`（每条带 `why`）；屏上循环指示 `x/11 → x/9`。
悄悄删掉的话「取料/回家」就凭空消失，看演示的人会以为功能没了——**撤出要留原因，这是运行镜像的诚实底线**。

**还有一条同族坑（本轮又踩）**：统计"折线穿过哪面墙"时，不能用"线段两端点在墙两侧"判定——路径会在门洞处**显式落一个正好压在墙面上的顶点**，此时乘积=0，整段漏计（mock 那版 `gateCrossings` 就是这样报 0 次穿门）。
正确做法是按**顶点的侧向符号变化**计数：遇到 0（正好压墙）保持上一条侧向不变，等下一个非零侧向再判定是否穿越。场景自检 `auditRoutes()` 的 `transits` 就是这么算的，routecheck 断言恰 4 次（两道门 × 去/返）。
