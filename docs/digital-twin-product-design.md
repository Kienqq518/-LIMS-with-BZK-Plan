## 1. 定位：从「空间可视化」到「业务实时镜像」

一句话：**LIMS 里每一份单据、每一支样品、每一台设备，在孪生里都有一个位置、一个状态、一段轨迹。**

- 孪生不是独立产品，是实验室业务管理系统的**空间化视图**：业务数据是唯一事实源，孪生只消费、不生产（延续 T0 契约原则）。
- 与「数字可视化」应用的分工：可视化=指标视角（图表/BI），孪生=场景视角（空间/实体/事件）。
- 与透明实验室的关系：报告码公开页是**冻结快照**（给客户看结果），孪生是**运行镜像**（给内部看过程、给高等级客户看回放）。

三条红线（继承路线图治理底线）：
1. 孪生展示的业务状态必须与 LIMS 台账/流程实时一致，禁止装饰性假状态；
2. 缺数据源的位置显式「无实时数据」，不造假动画；
3. 对外视角受分级公开引擎门禁，不越级泄露。

## 3. 双向联动交互（孪生的灵魂）

### 3.1 LIMS → 孪生（「带我去看」）
- 关键详情页加**「孪生视图」按钮**：委托详情、样品详情（sample-data-detail）、设备台账（equip-mgmt 行操作）、试验记录（test-record）、报告编制。
- URL 参数协议：`tour-lab-v3-1.html?focus=sample:SPL2026001` / `?focus=equip:eq_qj36` / `?focus=entrust:WT2026001`。
- 到达行为：镜头飞行至目标房间 → 目标实体高亮脉冲 → 自动弹出对应详情卡；无该实体数据时落位房间并诚实提示。

### 3.2 孪生 → LIMS（「点我看档案」）
- 点设备 → 设备台账气泡（复用 equip-mgmt 名称悬停气泡组件）→「打开设备管理」深链 `equip-mgmt.html?code=LX-05`；
- 点样品 → 样品详情/旅程时间轴；点工位 → 该台位当日试验记录；点人员 → 资质档案；点报告码 → report-verify 公开页。
- 实现：`tour-bridge.js` 已有 postMessage 通道，扩展为导航指令总线（`{type:'open', target:'equip:eq_qj36'}`）。

### 3.3 事件流驱动
- LIMS 流程动作（收样确认、开始试验、复核提交）→ 孪生网关 → SSE → 场景高亮/轨迹线追加。
- 原型阶段用 `mock/scene-data.js` 的事件序列预演（D2 前不接真实推送）。

## 6. 技术实现要点

- 渲染层：现有 three.js 包不动；新增三个业务叠加层——**轨迹层**（样品路径线）、**角标层**（设备/人员状态）、**事件层**（高亮/脉冲），全部经 `NodeStore.subscribe` 同源驱动。
- 集成方式：短期 iframe + postMessage（tour-bridge 通道）；中期把孪生作为 TestOS 顶栏 pageTabs 的一级页签，与业务页同壳导航。
- 数据：孪生只读网关（`GET /twin/snapshot` + `SSE /twin/stream`），契约见 integration 文档 §2/§4；`LiveNodeAdapter` 三函数为唯一替换点。
- 深链参数统一小写命名空间：`focus=<type>:<id>`，type ∈ {sample, equip, entrust, report, room, person}。

## 8. 验收与演示脚本

**4A 闭环演示**（招投标场景 90 秒）：
扫样品标签 → 孪生定位该样品所在台位并回放已走轨迹 → 点设备弹出台账（校准证书/精度/履历）→ 扫码报告码核对公开页与孪生回放一致。

**每期验收清单**：
1. 孪生内任一实体的状态与 LIMS 页面显示一致（抽 3 台设备、3 支样品）；
2. `?focus=` 深链全部可达且诚实降级（不存在的实体不白屏）；
3. 对外回放视角字段集 = 报告等级公开矩阵；
4. `#req013-runtime-errors` 为空。

## 9. 度量

- 业务覆盖率：孪生可定位实体数 / LIMS 主数据总数（目标 D2≥80%）
- 联动使用率：经孪生深链打开业务页的次数 / 孪生访问次数
- 演示转化率：4A 脚本在售前场景的成单关联（人工标记）
