# 未来实验室数字孪生 · 总体设计方案（三源驱动）

> 2026-11-05 · 依据《无人化实验室测控技术架构图（应敏科技）》编制
> 姊妹文档：`digital-twin-integration.md`（数据契约/网关）、`digital-twin-product-design.md`（LIMS 业务融合）

## 1. 架构定位

架构图（图1）中，数字孪生系统位于右侧蓝色应用带，与「检测工位系统 / 数据可视化平台」并列，共同消费中间绿带三大系统的数据：

```
┌─ 设备层（左）────────────────────────────────────────┐
│ 制样设备1-4/检测工位(PLC·长江控制器·嵌入式·上位机软件)  │
│ AMR自主移动机器人 · 复合机器人 · 机器人调度系统         │
│ 智能样品货架1/2 · 样品暂存架                          │
├─ 执行/集控（中绿带）──────────────────────────────────┤
│ ① 无人检测调度系统：预派工单·检测任务调度·机器人调度    │
│ ② 检测数据采控系统：试验数据/任务分配/前置状态         │
│ ③ 试验设备集控系统：设备运行行为·机器人运动行为·数字孪生│
├─ 物联接入（右绿带）───────────────────────────────────┤
│ 智慧实验室物联网系统：门禁·电梯·安全联动·图像识别App·   │
│ 组态物联终端·第三方传感器 → 监控/灯光/空调/其它物联     │
├─ 应用层（右蓝带）─────────────────────────────────────┤
│ 应敏LIMS · 检测工位系统 · 数据可视化平台 · 数字孪生系统 │
│ 第三方上位机：南瑞·华云等；手机监控App·安全管家          │
└──────────────────────────────────────────────────────┘
```

**数字孪生 = 三源汇聚的空间化消费端**：不自采数据、不下发控制指令，只做「镜像 + 上浮 + 回放」。控制链路（调度→机器人→设备）永远绕过孪生，孪生断线不影响生产。

## 2. 三大数据源与孪生实体映射

| 数据源 | 提供什么 | 孪生实体/表达 | 更新频率 | 断流降级 |
|---|---|---|---|---|
| **① 无人检测调度系统** | 预派工单、检测任务队列、机器人/AMR 实时位置与目标点位、上下料/开关门动作事件、货架储位占用 | 机器人移动体（106 场景内位置+轨迹线）、工单光牌（委托→台位）、货架储位格（占用/空） | 位置 1–5s 推送；事件即时 | 机器人停走并标「调度离线」，保留最后位置与时间戳 |
| **② 检测数据采控系统** | 设备运行参数（电压/电流/温度曲线）、试验开始/结束、采集数据、前置状态（设备就绪/占用）、上位机软件状态 | 设备台位运行态角标（在测/空闲/占用）、参数浮窗（Beats 节拍卡）、流程节点时间线 | 参数 10s–1min；节点事件即时 | 显式「无实时数据」，绝不用曲线循环动画填充 |
| **③ 智慧实验室物联网系统** | 门禁开关、电梯状态、灯光/空调、视频监控与图像识别结果、组态物联终端传感器（温湿度/烟感/水浸/气体/开关量）、第三方传感器 | 现有 16 个 IoT 节点（快照 schema 已就绪）+ 新增 门禁/灯光/空调 节点类型；相机节点 videoSource 回源 | 秒级–分钟级；告警即时 | 节点 status=offline，保留最后 updatedAt |
| （旁路·**二期**，PRD-v1 §5）应敏 LIMS | 委托/样品/设备台账/人员资质/耗材/报告 | 业务对象深链与档案弹卡（见 product-design §2） | 流程事件驱动 | 台账字段静态兜底 |

**统一契约**：三源全部归一到既有快照 schema `{nodeId,status,values,updatedAt,dataState,source}`，`source` 扩展枚举 `'daq'|'dispatch'|'iot'|'lims'`；机器人/样品这类**移动实体**增加 `position{x,y,z}` 与 `path[]` 字段（three-world-m 坐标，沿用 CAD 空间）。

## 3. 接入技术方案

- **协议适配**：调度系统（HTTP API + WebSocket/MQTT 位置流）→ `dispatch-adapter`；采控系统（数采已有回传通道，OPC-UA/Modbus 归口在采控侧）→ `daq-adapter`；物联网系统（组态物联终端经数采，门禁/电梯/灯光走 IoT 平台开放 API）→ `iot-adapter`。三个 adapter 只做**下发任务/消费回传→归一化快照**（与八维度适配器契约同构）。
- **孪生网关（BFF，新建）**：聚合三源 → `GET /twin/nodes`（配置+台账关联）、`GET /twin/snapshot`（全量 replace 语义）、`SSE /twin/stream`（增量 patch + 事件）。前端唯一替换点仍是 `LiveNodeAdapter{loadInitial,subscribe,decode}`。
- **坐标对齐**：调度系统地图坐标 → three-world-m 需一次性标定映射（现场选 3 个基准点求仿射变换），标定结果存 `data/dispatch-calibration.json`；未标定前机器人位置显示为「相对轨迹」不显示绝对点位（诚实降级）。
- **时钟**：全链路 NTP 对齐，快照 `updatedAt` 缺失视为事故；回放按时间锚（复用 P1 预留结构）。
- **安全**：网关只读；对外视角走分级公开引擎门禁；与控制网物理/逻辑隔离（孪生只有「看」没有「控」）。

## 4. 应用层设计（风格系统 · 按参考图 2–5）

**视觉基调**：高调白（high-key）等距场景 + 悬浮白卡 + 5M1E 维度导航；与现有白蓝包同一方向，叠加四件套：

1. ~~**5M1E 顶栏胶囊**（人/机/料/法/环）~~　**【已取代 · 2026-11-05 决策 Q7】** 五切片全部撤下：数据面不齐（人需定位/门禁、法需标准版本绑定），实测会把「料/法/环」做成空按钮。改为 `docs/digital-twin-product-plan-v2.md` §5.1 的三层控制：叙事（S1/区域下拉/S3）+ 图层（路径/标签/分区/墙体/热力）+ 动作（系统流/收起/低配）。
2. **Beats 节拍浮卡**——设备/工位上方白卡：节拍均值 min + 迷你波形（紫/橙/绿三色分级），数据源=采控系统任务起止时间。
3. **Grade A/B/C 告警分级**——红色胶囊+设备红框：A=停机/校准过期（如 DL-09）、B=瓶颈积压、C=阻塞（机器人未到达），对应安灯分级派发。
4. **安灯（Andon）卡片**——告警卡带设备图标+原因+「安灯呼叫」动作，按级别派发到不同终端（手机App/工位屏/主任台）。
5. **调度轨迹层**——蓝色路径线+箭头+机器人光晕（调度系统位置流驱动），绿色 P 点=当前目标位。

**风格预览页**：`twin/future-lab/twin-style.html`（真实 CAD 场景 + 上述叠加层，mock 数据），已可打开演示。

> **V1 范围修正（2026-11-05，以根目录 `PRD-v1.md` 为准）**：V1 = S1 总览 + S2 无人化试验区重点监控 + S3 近 24h 告警回溯；交付形态为 Web 大屏（1920×1080 基准）+ Docker 一键演示（Mock）；LIMS 深链与对外回放、权限管理均为二期。下表 D2 的「判定规则告警」V1 内以三源 mock 告警流实现，不依赖 LIMS。

## 6. 验收红线（每期）

1. 三源任一断线，孪生显式降级（offline/stale/missing），无假数据；
2. 孪生无任何控制下发能力（安全架构评审项）；
3. 机器人/样品位置与调度系统实物抽查一致（±0.5m）；
4. 对外回放不越级泄露；`#req013-runtime-errors` 为空。
