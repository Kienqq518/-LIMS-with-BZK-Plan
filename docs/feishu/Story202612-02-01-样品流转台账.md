## 需求背景

实验室需要按「一件样品」查全库台账：这件样品现在在哪、检测到哪一步、结论是什么、报告和合格证在哪。现网 Web 没有独立的样品全库查询；委托详情里的「样品台账」只是本单时间线。App「样品查询」已有按样品编号查的能力，但状态把流转与检测结论混在一起，详情是折叠区而不是分区 Tab，也没有留样/退样二选一、18 步任务节点、报告编制签发字段等口径。

本 Story 把 Web 新增「样品台账」、App「样品查询」对齐为同一套只读能力。Web 原型已按下文实现（`sample-ledger.html` / `sample-ledger-detail.html`）。App 按同一口径改造，保留手机扫码。

## 需求目标

- 一行一件样品。同一委托多件样品多行。不能在台账里收样、发样、领样、还样、退样、改判。
- 流转状态与检测结果分开：流转看实物/任务进度，检测结果看出具结论。
- 详情默认打开流转台账。主体分四个区：样品信息、检测信息、流转台账、结果报告。
- 还样之后只能走留样或退样其中一条。未还样则两条都不出现。
- Web、App 查询条件、名单列、详情字段、状态口径一致。Web 不做相机扫码；App 保留扫码。

## 需求范围

- **覆盖**：Web 样品管理 › 样品台账（合格打印之后）；App 样品查询（能力对齐，菜单名可保留「样品查询」）。名单查询、样品详情、打印标签入口、合格证证面、报告文档字段。
- **系统**：轻量 LIMS、物资 LIMS、TestOS App。
- **边界**：不替代收样 / 制备 / 发样 / 还样 / 退样 / 合格打印。委托详情现有「样品台账」弹窗是本单时间线，与本页并存，弹窗提供「在样品台账中打开」。数字孪生 102 房间「样品台账」是库存统计块，不是本页。无独立退回管理菜单。

## 流程

1. 有权限的角色从菜单进入样品台账 / 样品查询。
2. 按委托编号、样品编号、样品名称、送检单位、样品大类、当前节点、流转状态、检测结论、检测时效、日期范围筛选。名单按样品编号倒序。
3. 点样品编号或「查看」进详情。默认「流转台账」。
4. 详情只读：看样品标识/来源/接收、试验项与原始记录、实物路径、检测结论与报告文档。合格样品直接看合格证证面。可打印样品标签。
5. 返回名单时保留查询条件与滚动位置。

## Web 端

**入口与权限**：样品管理 → 样品台账，排在合格打印之后。系统管理员、样品库管理员、检测员、报告审核员可进，全部只读。无权限时菜单不出现，直开 URL 出无权限提示。

**查询**：委托编号、样品编号、样品名称、样品大类、送检单位、当前节点（多选，委托登记 → 任务完成 18 步）、流转状态、检测结论、检测时效（未逾期 / 逾期）、**日期范围放最后**（委托日期或收样日期 + 开始 ~ 结束，空表示不限）。按钮：查询、重置、导出当前筛选结果。查询区不提供排序，固定样品编号倒序。Web 样品编号框接收扫码枪或粘贴，回车即查，不做相机扫码。

**名单列**：序号、样品编号（可附「逾期 n 天」）、委托编号、样品名称、规格型号、送检单位、联系人、联系方式、收样时间、检测状态（未收样 / 未检测 / 检测中 / 已检测）、检测结论、检测员、检测时间、下次检测日期、退样时间、流转状态、当前节点、委托日期、要求完成日期、样品大类、操作（查看 / 打印标签）。序号、样品编号、操作锁定。检测结论为「/」表示尚无结论。合格可点开合格证。逾期看报告签发是否在要求完成日期前完成，与检测结论「已过期」分开。未收样的收样时间 / 检测员 / 检测时间 / 下次检测日期 / 退样时间为 —。退样时间仅还样后走退样才有值。

**详情页首**：样品编号、名称、流转状态、检测结果。有样品别名且与名称不同时，名称位展示「别名（样品名称）」；无别名只显示样品名称。检测结果为「/」时页首不展示斜杠。下一行：委托编号、当前任务节点。点当前节点弹出「合同流程」弹窗（与顶栏搜索委托编号回车同一套），不在页内展开。

**详情四个 Tab**（默认流转台账）：

1. **样品信息**：样品标识（编号、名称、大类、产品标记、型号/分类、规格、检测类别、数量）+ 来源信息（委托编号、委托单位、委托日期、任务类型、要求完成日期、生产厂家、生产厂家地址、制造商、制造商地址）+ 接收信息（收样时间、收样人、收样状态、送样方式、送样人、送样人联系方式、到样情况、样品图片）。下次再检日期不在本 Tab。
2. **检测信息**：试验项表（试验项、检测依据、检测员、状态、完成时间、说明），**不展示进度条**。原始记录单列与委托详情一致：序号、名称、覆盖样品、生成模式、生成时间、状态、操作。
3. **流转台账**：当前存放位置 + 实物路径表（节点、状态、办理人、地点、时间、说明）。
4. **结果报告**：检测结论（检测结果、出具时间、结论说明、下次再检日期）+ 合格证证面直接展示（不跳转）+ 报告文档。

**出具时间**：该样品最后一项试验项完成上传的时间。尚有试验项未完成时显示 —。

**报告文档**：已生成报告时展示报告编号、报告状态、报告生成时间、编制人、编制日期、审核人、审核日期、签发人、签发日期、当前节点。未生成报告只提示「该样品尚未生成报告」，不铺空字段。审核中时审核日期 / 签发人 / 签发日期为 —。

Web 原型截图已贴在飞书正文：名单查询、页首别名、样品信息、检测信息、流转台账、合格结果报告、在检未出报告、审核中报告字段。

## App 端

App 现网菜单为「样品查询」（`src/components/lims/sample-query.tsx`）。本 Story 不另开菜单，把该页能力对齐 Web 样品台账。菜单名可继续叫「样品查询」，页面标题与能力按台账口径。

**相对现网要改的点**：

1. **状态拆开**：现网把待收样 / 检测中 / 合格 / 不合格 / 已过期混在一个状态里。改为与 Web 相同：流转状态（待接收 / 待检 / 在检 / 待审核 / 已完成 / 留样 / 已处置 / 退回）+ 检测结果（合格 / 不合格 / 已过期 / /）。
2. **查询**：补齐当前节点（18 步多选）、流转状态、检测结论、检测时效、日期范围（委托日期或收样日期 + 起止，放在查询条件最后）。名单列与 Web 一致（含规格型号、送检单位、联系人、联系方式、收样时间、检测状态、检测员、检测时间、下次检测日期、退样时间）。按样品编号倒序。导出当前筛选结果（若 App 提供导出）。
3. **扫码**：App 保留相机扫码 / 相册选标签，扫到样品编号即查。这是相对 Web 的差异，Web 只接收扫码枪或粘贴。
4. **详情结构**：现网是多段折叠（基本信息 / 委托 / 样品 / 台账 / 进度 / 结果 / 记录 / 报告）。改为与 Web 四区一致：样品信息、检测信息、流转台账、结果报告。可用顶部 Tab 或等价分段，默认打开流转台账。
5. **页首名称**：有样品别名且与名称不同时展示「别名（样品名称）」；检测结果为 / 时页首不展示斜杠。
6. **检测信息**：去掉试验项进度条。原始记录列与 Web / 委托详情一致。
7. **流转台账**：正向路径含制备（未发生则不写）。还样后留样或退样二选一；未还样两条都不出现。回退行标「回退」。
8. **结果报告**：下次再检日期放进检测结论。出具时间 = 最后一项试验项完成上传时间。合格证直接展示证面。报告文档补齐生成时间、编制人、编制日期、审核人、审核日期、签发人、签发日期。
9. **操作**：查看详情、打印样品标签。不能在查询页做收样/发样/还样/退样/改判。

App 演示数据委托号写成现网 `SC2026/xxxx`，与 Web 种子同源口径（合格留样、同委托在检、待接收、不合格已处置、已过期、含退回发样）。

## 规则

**流转状态判定**

| 状态 | 判定 |
|---|---|
| 待接收 | 尚未收样 |
| 待检 | 已收样、试验尚未开始 |
| 在检 | 试验进行中 |
| 待审核 | 试验完成，处于组内审核到报告审核 |
| 已完成 | 已完成报告签发且未走留样/退样 |
| 留样 | 还样后走留样 |
| 已处置 | 还样后走退样 |
| 退回 | 当前处于回退节点（如退回发样） |

**流转台账（实物路径，不是整单 18 节点）**：委托登记 → 收样 → 制备 → 发样 → 领样 → 检测 → 还样 → **留样或退样（二选一）**。制备未发生不写该步。未发生的正向步骤灰色排在后面。同一环节多人各记一条。回退橙色标「回退」。只读，不能补录。

**检测结果**：合格 / 不合格 / 已过期（超过要求完成日期仍未出结论） / /（尚无结论）。逾期标签看报告签发是否在要求完成日期前完成，与「已过期」分开。

**跨页**：样品编号 → 本详情；委托编号 → 委托详情；合格 → 合格证；报告编号 → 对应报告；委托详情「样品台账」弹窗 → 「在样品台账中打开」并带该委托编号过滤。
