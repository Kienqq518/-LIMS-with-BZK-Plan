## 需求逻辑

### 1. 问题与结论

**问题（对应项目部 #79）**：合格证 QR 若编码完整验真 URL（常 60～200+ 字符），码点密集，小尺寸打印时微信/支付宝/相机识别率低。

**结论**：**局域网与公网均可采用短链 QR**。本质是 QR 只编码短 URL，短链服务查表后 **HTTP 302** 跳转验真页；与部署在公网还是内网无关，只需把短链域名换成该环境可达地址。

| 维度 | 公网 | 局域网 |
|------|------|--------|
| 架构 | 短链 → 302 → 验真 H5 | 相同 |
| QR 示例 | `https://lims-plan.vercel.app/l/Ab3K9` | `http://lims.local/l/Ab3K9` 或内网 IP |
| 码短、易扫 | ✅ | ✅ |
| 外网 4G 无 VPN 扫码 | ✅ | ❌（访问不到内网） |

### 2. 扫码链路

```
用户扫码 → 打开短链 URL → 短链服务查 code → 302 → 验真 H5（试样信息 + 验真结论）
```

### 3. 数据模型（映射表）

| 字段 | 说明 |
|------|------|
| `code` | 5～8 位短码，写入 QR |
| `sample_no` | 试样编号 |
| `entrust_no` | 委托编号 |
| `status` | valid / expired / revoked |
| `reinspect_date` | 再检日期（过期判定） |
| `long_url` | 完整验真地址（302 目标） |
| `created_at` | 创建时间 |

**生成时机**

- 报告签发及后续流程**首次**打印合格证时，按试样生成唯一短链。
- 同一试样重复打印：**复用**已有短链（未作废时）。
- 流程回退至「报告签发及之前」：**自动作废**（`revoked`）。

### 4. 验真判定

**有效**（「短链有效，验真通过」）需同时：

1. 短链存在；  
2. 委托处于报告签发及后续；  
3. 当前日期 ≤ 再检日期；  
4. 状态为 `valid`。

**无效**（「短链无效，无法验真」）：短链不存在 / 超过再检日期 / 流程回退作废 / 手动作废撤回。

**原型演示码**：`Ab3K9` 有效 · `Ex1p1` 过期 · `Rv0k1` 回退作废 · 任意不存在码 → `cert-verify.html?code=XXXXX`

### 5. 局域网部署要点

- 推荐拓扑：手机（同局域网）→ 内网 DNS/Nginx → 短链服务 → 302 → 验真 H5/API。  
- **优先内网域名**（如 `lims.local`），避免 IP 变更导致已打印标签失效。  
- 短链服务可嵌入 LIMS 网关，不必独立产品。  
- 隔离网不依赖公网 CDN/第三方短链；生产 QR 建议本地库生成。  
- 若外部客户也要扫码：评估 DMZ 公网短链网关，或内/公网两套 Base 共用同一 `code` 映射表。

### 6. 与样品标签 QR 的边界

- **合格证**：短链验真（本节）。  
- **样品标签**：内部流转码，落地展示标签已配置字段，**不走**合格证短链验真协议。

### 7. 配置项（建议）

- `cert.shortlink.base`：短链 Base URL（环境配置）  
- `cert.shortlink.days`：短链有效期天数  
- 打印模块仅在门禁通过后生成/复用短链

### 8. 实施 checklist（摘要）

1. 确定内网短链 Base（域名优先）  
2. 映射表 + 作废策略（含流程回退）  
3. `/l/{code}` 302 接口  
4. 验真 H5 有效/无效逻辑  
5. 打印接入 + 本地 QR 生成  
6. 真机微信/支付宝在内网 WiFi 验收
