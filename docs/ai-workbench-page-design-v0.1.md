# AI 助手 · 样品配置工作台 页面交互设计 v0.1

> 定位：AI 助手模块下的新页面。把客户实验室的**检测能力范围表 + 检测报告/原始记录单 + 检测依据标准文件**，
> 变成系统能读懂、人也能读懂的 **Excel 配置包**，再把配置包拆解入库到「检测标准库 → 样品数据」。
> 接口契约见 `docs/standard-library-excel-contract-v0.2.md`（22 张 sheet / 29 条校验规则）。
> 实测基线：DS 实壁类塑料电缆导管一份 Word 稿 → 22 sheet / 200 参数 / 16 试验项 / 114 条待定项（范围级 6 / 字段级 108）。

---

## 一、三条铁律（先定死，界面围绕它长）

1. **任务边界 = 一份标准文件。** 一包可以多任务，但一个任务只处理能力范围里的一份标准文件。
   任务列表是页面的一等公民，不是一句话的附属品。
2. **F1 / F2 / F3 可独立进入，不强制串行。** 客户可能只要 F1（拿 Excel 自己改），可能只要 F3（专家线下已经定好稿）。
   任何一步都能单独跑，缺输入时给"从哪一步补"的引导，而不是报错拦死。
3. **AI 的产出永远是"待复核草稿"，定稿权在人。** F1 不承诺正确，只承诺：每条都有来源、有置信度、
   不确定的都变成问题问出来。入库前必须有"真缺陷 = 0"的硬门。

---

## 二、两个档位：同一页面，差别只在资产归属

| | 内部档（业务专家 + 实施工程师） | 客户档（客户实验室自己用） |
|---|---|---|
| 能新增标准族 | 可以，从报告模板/标准 PDF 现推 | 同样可以 |
| 定稿去向 | 回流成**公司资产**，下个客户直接命中 | 只进**本客户环境**，不污染别人 |
| 标准文件库 | 全局元数据 + 拆解成果共享 | 同左；文件本体按客户隔离 |
| 可见范围 | 全部客户任务、复用统计、契约缺陷看板 | 仅本客户任务 |
| 提问风格 | 允许"改契约/改算法"级问题 | 只问业务问题，工程问题转给实施侧 |

档位**由账号角色决定，不让用户手选**（选错档会把客户数据回流进公司资产）。内部账号可在页面右上角切"以客户视角预览"，只读。

## 三、页面骨架

```
+------------------------------------------------------------------------+
| 样品配置工作台        [档位徽标] [标准文件库] [稿件模板] [历史任务]     |
+----------+--------------------------------------------+----------------+
| 任务列表 |        主工作区（随步骤切换）              | 对话 / 提问区  |
| (左栏)   |  F1 上传与拆解  F2 校稿定稿  F3 预检入库   | (常驻右栏)     |
|          |                                            | 问题卡片流     |
| + 新建任务|                                            |                |
+----------+--------------------------------------------+----------------+
```

- **左栏 任务列表**：一行一个任务，显示 `标准号 / 进度条（F1→F2→F3）/ 稿件状态徽标 / 待定项计数 / 最近操作人`。
  状态徽标只有 5 个：`草稿` `待补料` `校稿中` `已定稿` `已入库`。
- **中栏 主工作区**：F2 是结构化表格（22 张 sheet 的标签页），F1 是上传与拆解日志，F3 是预检报告与入库进度。
- **右栏 对话区**：不是聊天框，是**问题收件箱**。AI 的话、人的答、系统的动作都落在这里，可回溯。
- 三栏宽度可拖，中栏最小 900px（表格列多，压缩会毁掉可读性）。

## 四、F1 生成初版 Excel 合集

### 4.1 上传区（三类料，一次收齐）

| 槽位 | 必填 | 说明 |
|---|---|---|
| 检测能力范围表 | 必填 | PDF。决定"哪些样品、哪些试验项、量程到哪" |
| 检测依据标准文件 | 必填 | PDF，可多份。是**唯一权威来源**，所有值最终要在这里验证 |
| 检测报告 / 原始记录单 | 可选 | docm/docx/pdf。用来补能力表里没写的样品型号、参数命名 |

三个槽位不是一次性上传完才能走：**先传能力表就能起跑**，标准文件后补时 AI 做增量验证并降级置信度。

### 4.2 拆解的四个阶段（界面上是一条可见的进度带，每段可展开日志）

1. **识别**：读 PDF，抽标准号 + 标准名称（从正文抽，不用用户给的文件名，不用正则猜）。
2. **命中库**：拿规范化编号去标准文件库比对。命中则弹一个**范围级问题**：
   「库里已有 GB/T 12706.2-2020，且已拆解过（成果版本 v3-final）。
   本次按 **库内成果** 拆（快，直接复用），还是按 **你上传的这份** 重新拆（慢，但以你的文件为准）？」
   未命中则登记新标准，问是否入库共享（客户档默认只进自己环境）。
3. **任务发现**：见第七节。能力表覆盖十几份标准时，AI 先给"将拆成 N 个任务"的清单让人确认，再开工。
4. **生成 + 提问**：产出稿件 v1-draft，同时把不确定项变成问题。

### 4.3 提问分两层，界面必须长得不一样

| | 范围级 | 字段级 |
|---|---|---|
| 何时问 | **生成前**，答完才继续 | 生成中/后，不阻塞出稿 |
| 例子 | 型号挂哪个样品 / 拆几个任务 / 要不要拆其他型号 | 这个参数是实测还是计算 / 修约映射到哪种算法 |
| 界面 | 独占对话区顶部，**阻塞态横幅**，答完才能点"继续生成" | 问题收件箱里按 sheet 分组的卡片列表 |
| 数量级 | 个位数（DS 实测 6） | 上百（DS 实测 108） |

字段级问题的界面规则（114 条实测规模下这是生死线）：

- **按 sheet 分组**，组头显示 `sheet 名 / 条数 / 已答 / 全组采纳默认值` 一键。
- 每条给 **默认值 + 置信度**，不给空白输入框。人只做"接受 / 改一个 / 跳过"。
- 选项式优先：2–4 个候选 + "其他（补充说明）"。纯开放问题占比要能统计。
- 同因合并：`各试样冲击结果` 在 T07/T15 各撞一次，折叠成一条"应用到这 2 处"。
- 支持**批量答**："下拉选项全部按 合格/不合格" 一句话覆盖 N 条，AI 回显受影响行清单再落。
- **跳过（延迟决策）只给字段级**：字段级问题可跳过，数据先按 AI 当前最优猜测占位、卡片标灰，
  不阻塞生成稿件、也不阻塞定稿；F3 预检把跳过项集中成「二次确认」清单再问一次，
  二次仍跳过则由 AI 自决落库并通知客户（详见契约 C0 跳过口径与 V24/V25）。
- **范围级不允许跳过**：它决定最终输出的结构（拆几个任务、型号归谁、试验项挂哪层），
  交给 AI 自决等于把整块数据的层级押上去，回改要推翻已入库内容。界面不提供跳过按钮，
  出口只有两个：回答，或补料后再回答。

### 4.4 缺料与失败

| 情况 | 行为 |
|---|---|
| 能力表提到某试验项，库里和上传里都没有对应标准文件 | 阻断该任务，其他任务继续；问题卡片给"上传标准文件 / 跳过 / 按报告模板推" |
| PDF 是扫描件且 OCR 置信度低 | 该页所有值降级为"未验证"，不硬填；提示重传清晰版 |
| 报告模板与标准文件数值冲突 | 双值并列显示，**冲突不自动取舍**，标准文件侧标"权威"，进字段级问题 |
| 单任务解析超时/崩溃 | 任务级重试，已完成的 sheet 保留，不清空整包 |

## 五、F2 专家校稿定稿

### 5.1 主视图 = 表格，不是文档

22 张 sheet 做成标签页（顺序 = 导入拓扑顺序），每页是**可编辑的结构化表格**：

- 单元格保留**来源角标**：`已验证 / 冲突 / 未验证 / AI推断 / 无来源`，hover 出证据（标准号+条款+页码 / 报告原文）。
- 右侧抽屉显示选中行的全字段 + 该行的问题列表 + "这行从哪来"的溯源链。
- 顶部常驻：**未答问题数 / 阻断数 / 真缺陷数**，三个数不为 0 时"定稿"按钮置灰并写明原因。
- 派生列（如 `报告展开式`）只读，改源列即重算。

### 5.2 三种改法，都留痕

1. **直接改单元格**：即时生效，记 `人工修改`，来源角标转"人工确认"。
2. **对话批量改**：「把 90 里所有 450/750V 的绝缘标称厚度改成按 GB/T 12706.1 表3」
   → AI 先回显**影响范围预览**（命中 12 行，列出）→ 人确认才落；落完可一键撤销。
3. **下载线下改完再上传**（必须支持，专家习惯 Excel）：
   上传后跑**三方对比**：`库内基线(上次定稿) ↔ 本次上传 ↔ AI 原稿`，
   界面只列**差异**，每条差异标出是"人改的"还是"AI 重算的"，支持逐条接受/回退。
   冲突规则：人改的优先；人改的与校验规则冲突时不覆盖，转为问题。

### 5.3 版本

`v1-draft`（AI）→ `v2-review`（校稿中，每次保存生成快照）→ `vN-final`（定稿，锁定）。
定稿稿件是**不可变**的；要再改就开新版本，旧版本仍可下载与对比。
稿件内按**样品分块**定稿：A 样品定稿不影响 B 样品。

## 六、F3 拆解入库

### 6.0 跳过项二次确认（入库前的必经环节）

F3 顶部四格摘要：`真缺陷 / 待答即消除 / 跳过待二次确认 / AI 自决落库`。
跳过项在这里重新列出，每条给出 **AI 拟取值 + 依据 + 出处**，三个动作：

| 动作 | 结果 |
|---|---|
| 选一个候选 | 转 `已答`，从二次确认清单消失 |
| 仍跳过，AI 自决落库 | 转 `AI自决落库`，写 `自决依据`，进入自决清单并计入通知 |
| 回原问题 | 跳回 F1 收件箱定位该卡 |

**V24**：还有未二次处置的跳过项 ⇒ 入库按钮置灰。
**V25**：`AI自决落库` 缺依据或缺通知 ⇒ 不得入库。
入库后生成「AI 自决清单」（按合并组列，不逐条刷屏）：每条写 AI 落库取值、依据、涉及处数、
回改路径（sheet · 行键 · 列），通过站内消息 + 清单通知客户，并给深链回改。

### 6.1 两段：预检（只读）→ 入库（写）

- **预检**：跑 D0 全部规则，出报告，样式同 `out/precheck-DS.md`，明确区分
  `真缺陷`（挡住，必须回 F2 或改契约）与 `回答待定项即可消除`（挡住但可点进去答）。
- **入库**：只在 `真缺陷=0 且 待定项=0（或已显式忽略并记原因）` 时开放。

### 6.2 入库前必问的两类归属（系统里没有的东西，AI 不能自己建）

1. **大类**：「这批样品归到哪个大类？」→ 选已有 / 新建（新建需给名称+编码前缀）。
2. **样品分类层级**：按 10_分类路径 逐级比对，缺失的层级逐个问：
   「库里没有『实壁类塑料电缆导管』这一层，挂在『电缆保护管』下新建，还是挂到你选的别的节点？」
   AI 可以**辅助创建**（给出建议名称、层级、与标准文件节点的父子关系），但**必须人点确认**。

### 6.3 事务边界

- 按**样品分块**，一块一个事务：一块失败只回滚这块，其余保留。
- 失败原因原样贴回对话区，并给出"改哪张 sheet 的哪一列能过"的定位链接。
- 入库后任务状态转 `已入库`，给跳转：样品数据页（带定位到具体样品/型号/试验项的深链）。
- 重复入库保护：稿件指纹（任务键+样品键+行哈希集合）相同，提示"已入库，是否覆盖/新增版本"。

## 七、任务发现（能力表覆盖多标准时）

界面上是一张**任务清单预览表**，AI 先给、人再确认：

| 列 | 内容 |
|---|---|
| 标准文件 | 规范化编号 + 名称 |
| 层级角色 | 总标准 / 子标准 / 独立标准（如 DL/T 802.1 是"电缆保护管有哪些类型"的集合标准，802.3 是其中实壁类） |
| 覆盖样品 | 能力表里落到这份标准的样品与型号 |
| 库状态 | 已存档+已拆解 / 已存档未拆解 / 未上传 |
| 建议 | 独立成任务 / 合并 / 需补文件 |

规则：
- 只上传了总标准（802.1）但判断出各类型有各自子标准，告知"需按子标准各拆一个任务，预计 N 个"，
  缺的文件列清单让人上传；这些任务一定落在能力范围表之内。
- 标准文件里明确提到其他型号、但报告/记录单没提，问"是否一并拆解 型号 xxx/xxx"，以人答为准。
- 标准文件里有型号列举则 `区分型号=是`；没有则 `=否`（口径已定，不让 AI 自由发挥）。

## 八、状态与视觉

- 复用 `css/ui-baseline.css` + `js/ui-a11y.js`，与样品数据页同族（表格密度、蓝主色、圆角 4px）。
- 置信度五色：已验证 `#16a34a` / 冲突 `#dc2626` / 未验证 `#d97706` / AI推断 `#2563eb` / 无来源 `#94a3b8`，
  只用角标 + 文字，不做纯色块（色觉无障碍）。
- 长任务（拆解 200+ 参数）用**分阶段进度带**而不是转圈：识别 → 命中库 → 任务发现 → 逐 sheet 生成，
  每段显示耗时与产物行数，失败段可单独重试。
- 空态文案说清"下一步做什么"，不写"暂无数据"。

## 九、埋点（产品自己要用才能迭代）

每个任务记录：拆解耗时 / 范围级与字段级问题数 / 人工改动单元格数 / 批量指令数 /
线下往返次数 / 定稿前真缺陷数 / 入库失败块数 / **标准族复用命中次数**。
最后一个是这个产品能不能形成复利的唯一指标。
